## 2. 지켜야 하는 기존 최적화 장치

점검은 아래 장치가 **새 기능에도 똑같이 지켜지는지** 보는 일이다. 장치 하나라도 빠지면 그 기능이 문제다.

| 장치 | 내용 | 확인 방법 |
|---|---|---|
| ① 끄면 멈춘다 | 기능 스위치를 끄면 감시기 정지, 타이머 해제, 관찰자 무시 | 단계 2 표 |
| ② 보일 때만 한다 | 진행 바·막대 위치 읽기·자원 그래프는 그 화면이 보이는 동안만 | 화면을 닫고 타이머 목록 확인 |
| ③ 큰 일은 도우미 프로세스 | 설정 창·파일 선택·사용량 웹 조회·이미지 변환·첨부 처리는 끝나면 프로세스째 사라져 메모리를 모두 돌려준다 | `pgrep -fl DynamicMacNotch` |
| ④ 메모리 지킴이 | 5분마다 사용량을 재고 기준(기본 70MB, 설정 70~150MB)을 넘으면 캐시 비우기 → 쉬는 중이면 조용히 다시 시작. Liquid HUD가 떠 있는 동안은 건너뜀 | `MemoryGuard.swift`, `isIdleForRelaunch` |
| ⑤ 짧은 훅 프로세스 | 에이전트 훅은 이 앱 실행 파일을 `--agent-done/-ask/-live`로 잠깐 실행하고 끝난다. 본 앱을 오래 깨우지 않는다. 훅 한 번의 시작·종료 약 **7ms** [확인: 10회 측정 7~8ms] | 단계 4 |

## 3. 점검 규칙 (`AUDIT_GUIDELINE.md` §1에 더해)

- **사용자의 전역 설정 파일**(`~/.claude/settings.json`, `~/.codex/`, `~/.gemini/`)은 '연결·해제' 시험(임시 홈을 쓰는 `--agent-probe`)을 빼고는 읽지도 쓰지도 않는다. 훅 시험은 **시험 폴더의 작업 폴더 설정**(`.claude/settings.json` 등)에만 한다.
- 에이전트를 실제로 돌리는 시험은 토큰을 쓴다: 가장 작은 모델, 한두 문장 지시, 시험 폴더에서.
- 개인정보 점검은 **값을 출력하지 않는다**. 키 이름·길이·개수·권한 비트만 기록한다. 결과 파일에 곡 제목·프로젝트 이름·요청·이메일·경로의 사용자 이름을 남기지 않는다.
- 손쉬운 사용으로 읽는 시험은 제목·값의 **길이와 종류만** 기록한다.
- 측정은 **Mac을 건드리지 않을 때**와 **쓰는 중**을 구분해 적는다. 시험 앞뒤로 사용자 설정을 `defaults export`로 저장해 대조한다.
- 시험이 끝나면 `pgrep -fl "MacOS/DynamicMacNotch$"`로 **설치된 앱**이 떠 있는지 본다. 개발 빌드는 `--dev-run` 없이 열면 설치된 앱을 대신 연다.
- 개발 빌드에서만 시험한다: 알림 미리보기, `scripts/notchctl`, probe. 배포 빌드는 인자를 무시하므로 실패한 빌드 뒤에는 probe를 돌리지 않는다.
- 화면을 덮는 시험·클립보드 덮어쓰기·키체인·자격증명 읽기는 하지 않는다.

## 4. 단계별 계획

### 단계 0 — 기준선 측정
배포 빌드와 개발 빌드 모두 같은 Mac·같은 설정에서 잰다.
```
scripts/build.sh --zip                    # 배포 빌드, 경고 0건
bash release-idle.sh                      # 실행 직후 메모리, 대기 60초×3(타이머 깨어남·메모리), leaks
scripts/build.sh --dev                    # probe 5종이 모두 실패 0건
for p in display settings monitor tray agent; do "build/Dynamic MacNotch.app/Contents/MacOS/DynamicMacNotch" --$p-probe; done
bash stress.sh                            # 미리보기 380회: 회전마다 메모리, 끝난 뒤 메모리·leaks
bash repeat.sh                            # 홈 100회·화면 구성 20회·설정 창 10회·채팅 20회
```
(`release-idle.sh`·`stress.sh`·`repeat.sh`·`wk`·`send`는 작업자 Mac의 점검 도구다. `wk`는 `proc_pid_rusage`로 CPU·깨어남·메모리를 읽는다.)

기록할 기준값(직전 배포 1.5.1): 실행 직후 **18.5MB**, 대기 CPU **0.20%**, 미리보기 380회 **30.8~31.3MB(늘지 않음)**, leaks **0**, 설정 창 도우미 **42~59MB**(닫으면 반환), 검색 한 글자 **약 1.7ms**, probe 실패 0.

| 주석 처리된 코드, TODO·FIXME | `grep -rn "TODO\|FIXME\|^\s*//\s*[a-z]*(.*)"` | 0건 |

### 단계 3 — 누수·수명 (반복해도 느는지)
**반복 시험** — 각 동작을 반복하고 앞뒤에 `leaks <pid>`와 `footprint <pid>`를 잰다. 예열 5회 뒤를 기준으로 삼는다.

| 동작 | 횟수 | 합격 |

**정적 점검** — 수명이 의심되는 곳을 코드에서 열거한다.

- **타이머**: 코드의 타이머 25곳(`Timer(`·`Timer.scheduledTimer(`·`DispatchSource.makeTimerSource`)을 표로 만들고 모두에 ① 켜지는 조건 ② 끄는 조건(`invalidate`) ③ 간격을 적는다. 켜지는 조건 없이 항상 도는 것은 `MemoryGuard`(300초)·`Updater`(3,600초)뿐이어야 한다 [의심: 현재 목록 기준]. 위치: `DisplayNotch`, `MissionControlMonitor`(빠른 주기·보통 주기), `DownloadMonitor`, `HUDMonitor`, `ResourceSampler`, `FocusMonitor`, `CallMonitor`, `RecordingMonitor`, `NetworkMonitor`, `BluetoothMonitor`, `Updater`, `HelperApp`, `MemoryGuard`(2곳), `ScreenshotMonitor`, `TimerController`, `AgentLive`, `UsageWeb`, `AIUsage`, `AgentAsk`, `PermissionsManager`, `OutputRoute`, `MediaController`(2곳).
- **분산 알림 관찰자**(`DistributedNotificationCenter...addObserver`) 14곳(그중 1곳은 probe): 앱 수명 동안 **한 번만** 등록되는지, 반복 호출되는 곳에서 등록하지 않는지. 훅 프로세스 안의 관찰자(질문 훅의 ack 대기)와 probe의 관찰자는 프로세스가 끝나면 사라지므로 허용.
- **상한이 있는 보관**: 에이전트 세션 최근 작업 4개, `youTubeCache` 50개, 상세 완료 알림 기록 10초, 질문 대기열(상한 없음 [의심] — 훅이 많이 오면?), 곡 아트 1장(`adapterArt`)과 600px 이미지 1장.

- **열린 파일**: 훅·질문 파일, 채팅·메모 파일 핸들이 닫히는지(`lsof` 수가 반복 뒤에도 일정).

## 9. 한계

- **자동 시험 틀이 없다**(`Tests/` 없음): 검증은 개발 빌드의 probe와 측정 도구에 의존한다. 새 기능은 probe 검사를 함께 늘린다.
- **노치·여러 화면·실제 입력**은 자동으로 못 본다: 질문 팝업의 키보드 입력(한글 조합), 접힌 노치의 길게 누르기, 전체 화면 전환은 사람이 확인한다.
- **Codex·Antigravity의 전역 훅**은 실제 환경에서 끝까지 확인하지 못했다(문서와 작업 폴더 시험까지). 에이전트가 업데이트되면 훅 입력 모양이 바뀔 수 있어 연결마다 한 번씩 다시 본다.
- 에너지(배터리) 영향은 활동 상태 보기로 사람이 본다.
