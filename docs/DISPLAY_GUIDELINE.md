# 노치 — Mission Control 숨김과 다중 디스플레이 구현 가이드라인

작성: 2026-11-06 · 설계만 (구현 전) · 대상 버전 제안: 1.5.0(Mission Control), 1.6.0(다중 디스플레이) · 사용자 결정 반영 (§6)

두 기능의 구현 방향, 일어날 수 있는 충돌·오류와 해결 방법, 작동 방식을 정리한다.
수치는 이 Mac(MacBook Pro, Apple Silicon, macOS 27.3, 디스플레이 1대)에서 직접 잰 값이다. **디스플레이가 1대뿐이라 다중 디스플레이 동작은 직접 확인하지 못했고**, 그런 부분은 "미확인"이라고 적었다.

---

## 0. 결론

1. **Mission Control 숨김은 안전하게 만들 수 있다.** 판정 기준은 `WindowManager`가 소유한 **`Spaces Bar` 창**이 보이는지다. 앱 Exposé는 같은 `ExposeShieldWindow`를 쓰지만 `Spaces Bar`가 없어서, 쉴드 창만 보면 앱 Exposé를 Mission Control로 잘못 알게 된다 (§1.1).
2. **상시 감시(폴링)는 하지 않는다.** 창 목록을 한 번 읽는 데 0.17~0.65ms가 들어, 20Hz로 읽으면 CPU 1% 안팎이다 (현재 대기 CPU 0.12~0.2%). 대신 창 서버 이벤트(비공개)를 **"창 목록을 다시 확인하라"는 신호로만** 쓰고, 판정은 항상 창 목록으로 한다. 이벤트가 오지 않아도 느린 안전 점검이 바로잡는다 (§2.2).
3. **다중 디스플레이는 "공유 모델 1개 + 디스플레이별 화면 상태 N개"로 나눈다.** 미디어·트레이·메모·채팅·상시 표시 목록은 이미 하나뿐이라 "상호작용 결과가 모든 디스플레이에 적용"은 구조상 자연스럽게 된다. 새로 만들어야 하는 것은 디스플레이마다 따로 있는 **화면 상태(확장 여부·페이지·호버·눌림)**다 (§3.2).
4. **한 번에 확장되는 디스플레이는 1개로 제한한다.** 타이머·메모·채팅 입력·카메라가 모두 하나뿐인 객체라, 두 디스플레이에서 동시에 열면 충돌한다 (§3.5).
5. **먼저 Mission Control(작고 독립적), 그다음 디스플레이 계층 정리(동작 변화 없음), 마지막에 다중 디스플레이** 순서로 나눠 구현한다 (§4).
6. **사용자 결정이 모두 반영되었다** (§6). 외부 디스플레이를 연결한 뒤 §5.1의 사전 기록(부록 A의 도구)으로 미확인 항목을 채우고 구현을 시작한다. 중요한 알림의 기본 구성과 알림 범위 기본값은 제가 고른 값이라 §6의 "남은 확인"에 적었다.

## 1. 확인한 사실 (이 Mac에서 측정)

### 1.1 Mission Control의 창 신호

Mission Control을 `open -a "Mission Control"`과 키보드(⌃↑)로 열고 닫으며, 화면에 올라온 창의 변화를 기록했다.

| 상황 | 나타나는 창 | 판정 |
|---|---|---|
| 평소 | `Dock`의 `Wallpaper` 창만 | — |
| **Mission Control** | `WindowManager`의 **`ExposeShieldWindow`**(레벨 19, 화면 전체) + **`Spaces Bar`**(레벨 14, 위쪽 134pt) + `App Icon Window`(레벨 17) 여러 개 | **Spaces Bar 있음** |
| 앱 Exposé (⌃↓) | `ExposeShieldWindow` + `Label Window - <창 제목>`. **`Spaces Bar` 없음** | 아님 |
| 바탕화면 보기 (F11) | `ShowDesktopOverlay`(레벨 18). 쉴드 창 없음 | 아님 |
| 앱 목록 (`Apps`) | 해당 창 없음 (일반 앱 창) | 아님 |

- 실제 화면에서 **Mission Control 위에 노치가 그대로 떠 있었다.** 노치 패널의 창 레벨이 메뉴바 위(`mainMenu + 3`)이기 때문이다. 그래서 직접 숨겨야 한다.
- 창 이름은 비공개 구현이라 macOS 업데이트로 바뀔 수 있다. 그래서 판정 규칙을 한 곳(`MissionControlProbe`)에 모으고, 아래 §2.5의 "신호표 점검"을 릴리스 전 항목에 넣는다.

### 1.2 시점 (열고 닫을 때)

| 순간 | 걸리는 시간 |
|---|---|
| 열기 명령 → 창 서버 이벤트 | 약 +63~83ms |
| 열기 명령 → 쉴드·Spaces Bar 창 나타남 | 약 +90~95ms |
| 닫기 명령 → 창 서버 이벤트 | 약 +52~68ms |
| 닫기 명령 → 쉴드·아이콘 창 사라짐 | 약 +380ms |
| 닫기 명령 → **Spaces Bar 사라짐** | 약 **+520ms** |
| 열고 닫는 애니메이션이 끝날 때 | 이벤트가 한 번 더 (+490~510ms) |

- **이벤트가 창보다 약 20ms 먼저 온다.** 이벤트를 받자마자 한 번만 확인하면 "아직 없음"으로 잘못 판단한다. 이벤트 뒤 약 1.2초 동안 짧은 간격으로 여러 번 확인해야 한다.
- 열자마자 0.35초 뒤 닫는 빠른 토글에서는 열기 명령 뒤 +70ms와 +920ms에, 닫기 명령 뒤 +490ms에 이벤트가 따로 왔다. **이벤트 개수나 순서로 상태를 세면 어긋나므로, 최종 상태는 창 목록으로만 정한다.**

### 1.3 비용

| 작업 | 1회 비용 |
|---|---|
| 창 목록 읽기 (`.optionOnScreenOnly`) | 0.65ms |
| 같은 호출 + 이름 필터 | 0.27ms |
| 창 목록 읽기 (`.excludeDesktopElements` 추가) | 0.17ms |
| 20Hz로 계속 읽기 | 약 1.3% (0.65ms 기준) |

### 1.4 창 서버 이벤트 (비공개)

SkyLight의 `CGSRegisterNotifyProc`로 번호 0~1999을 모두 등록해 어떤 것이 오는지 봤다 (등록된 것은 1488개).

- 오는 것은 **1508, 1325, 1326번** 뿐이었다 (처음 몇 번의 시험에서 1327, 1328이 한 번씩 더 보였지만 반복 시험에서는 나오지 않았다 → 쓰지 않는다).
- 36초 동안 열기·닫기 5쌍과 빠른 토글 3쌍을 했을 때 **총 65건이 모두 명령 뒤 1.2초 안**에 왔고, 관계없는 이벤트는 **0건**이었다. 평소에는 오지 않는다.
- **열림과 닫힘을 구별하지 못한다** (같은 번호가 양쪽에 온다). 그래서 "다시 확인하라"는 깨우는 신호로만 쓴다.
- 이 번호는 macOS 27.3에서 잰 값이고 비공개다. **다른 버전에서는 오지 않을 수 있다.** 이 앱은 이미 SkyLight를 `dlsym`으로 쓰고 있어(잠금화면 창) 같은 방식으로 불러오고, 실패하면 조용히 안전 점검만 쓴다.
- 이벤트를 받으려면 앱의 실행 루프(`NSApplication.run`)가 돌고 있어야 한다. 일반 명령줄 도구에서는 0건이었다.

### 1.5 확인하지 못한 것

- **다중 디스플레이에서의 Mission Control** (창이 디스플레이마다 따로 생기는지, 모든 디스플레이에 동시에 뜨는지)
- Stage Manager, 전체 화면 앱의 Space 안에서 연 Mission Control
- 트랙패드 제스처와 핫코너로 연 Mission Control (키보드·`open`으로만 확인. 같은 창이 뜨므로 같을 것으로 보이지만 미확인)
- 다중 디스플레이에서의 모든 동작 (미러링, 잠금화면, 절전 복귀 포함)

외부 디스플레이를 연결한 뒤 §5.1과 부록 A의 도구로 확인한다.

## 2. Mission Control에서 노치 숨기기

### 2.1 구성 요소

| 구성 | 역할 |
|---|---|
| `MissionControlProbe` | 창 목록을 보고 "지금 Mission Control인가"를 정한다. 판정 규칙은 여기에만 둔다 |
| `PanelVisibility`(중재자) | 노치 창의 보임 여부를 **여러 이유의 합**으로 정한다 (§2.4의 7번) |
| `NotchViewModel.hiddenAmount` | 0(보임) ~ 1(숨김). 노치 도형의 폭을 줄이는 값 |

### 2.2 감지 방식

```
깨우기: 창 서버 이벤트(1508·1325·1326) 수신  또는  안전 점검 타이머  또는  앱 활성화·화면 구성 변경·절전 복귀
   ↓
확인(settle): 깨운 뒤 약 1.2초 동안 100ms 간격으로 창 목록을 읽는다 (최대 약 12회 × 0.3ms)
   ↓
판정: WindowManager의 "Spaces Bar" 창이 있으면 Mission Control
   ↓
보이는 중: 100ms 간격으로 확인(Mission Control 중에만), 사라진 것이 연속 2회(약 200ms) 확인되면 끝난 것으로 본다
```

| 항목 | 값 | 이유 |
|---|---|---|
| 평소 | 폴링 없음, 이벤트만 | 대기 CPU·깨어남을 늘리지 않는다 |
| 안전 점검 | 3초마다 (허용 오차 1.5초) | 이벤트가 안 와도 최대 3초 안에 바로잡는다. 0.27ms/3초 = 무시할 수준 |
| 이벤트 불신 | 안전 점검이 이벤트 없이 Mission Control을 먼저 발견하면 "이벤트 경로 불신"으로 표시하고 500ms 폴링으로 전환 | 다른 macOS 버전 대비. 이때 약 0.05% 정도 늘어난다 |
| 시작할 때 | 한 번 확인 | 앱이 Mission Control 중에 켜졌을 때 대비 |

### 2.3 숨김·복귀 동작

**숨김 (Mission Control 시작)**

1. 열려 있는 노치는 먼저 접는다 (눌림·호버·키 입력 포커스 정리). 입력 중이던 글(채팅·메모)은 그대로 보존된다.
2. 노치 도형의 **양쪽 폭이 줄어든다**: 물리 노치가 있는 화면은 노치 폭까지, 없는 화면은 가운데 점까지. 동시에 내용이 투명해진다 (약 0.2초).
3. 끝나면 창의 알파를 0으로 하고 마우스를 통과시킨다 (`ignoresMouseEvents = true`). **창을 내리지(`orderOut`) 않는다.** 내리면 Space 전환 때 깜빡이고, 다시 올릴 때 위치와 순서가 틀어질 수 있다.

**복귀 (Mission Control 끝)**

1. Spaces Bar가 사라진 것이 2회 연속(약 200ms) 확인되면 알파를 1로 올리고 폭이 원래대로 늘어난다 (약 0.28초).
2. 그 뒤에 마우스 처리를 다시 켠다 (`updateHover`가 현재 커서 위치를 다시 판단).

**규칙**

- 숨김 중 새 알림이 오면 **알림 표시 시간 타이머를 멈춰 두었다가** 복귀 뒤에 보인다 (통화 알림 등을 놓치지 않게).
- "동작 줄이기" 설정이 켜져 있으면 폭 줄이기 없이 0.1초 페이드만 쓴다.
- 숨김→복귀→숨김이 0.4초 안에 반복되면 숨긴 채로 둔다 (깜빡임 방지).

### 2.4 일어날 수 있는 충돌·오류와 해결

| # | 문제 | 해결 |
|---|---|---|
| 1 | **앱 Exposé·바탕화면 보기에서 숨겨짐** (Mission Control이 아닌데 숨김) | 쉴드 창이 아니라 **`Spaces Bar`**로 판정. 위 두 가지는 이 규칙에서 제외되는 것을 확인했다 |
| 2 | **이벤트가 창보다 먼저 와서 놓침** | 이벤트 뒤 1.2초 동안 100ms 간격으로 확인 (§1.2) |
| 3 | **빠르게 열었다 닫음** | 이벤트 수가 아니라 창 목록의 최종 상태로 정한다. 복귀는 2회 연속 확인 뒤 |
| 4 | **이벤트가 오지 않음** (macOS 업데이트로 번호가 바뀜) | 3초 안전 점검이 바로잡고, 이벤트 불신이 되면 500ms 폴링 |
| 5 | **숨은 채로 남음** (Mission Control이 아닌데 숨김) | 숨겨진 동안 100ms 확인이 계속 돈다. 앱 활성화·화면 구성 변경·절전 복귀·Space 전환 때도 강제로 다시 확인. 어떤 경우에도 확인 없이 숨김이 유지되지 않는다 |
| 6 | **Mission Control인데 안 숨겨짐** | 이벤트 약 70ms + 확인으로 평균 0.1초 안에 숨김 시작. 놓쳐도 3초 안에 안전 점검이 잡는다 |
| 7 | **잠금 화면 전환과 알파 다툼** — 지금도 `setMainPanelHidden`이 알파를 0/1로 정한다 | 알파를 직접 만지지 않고 **중재자**가 `보임 = !잠금중 && !MissionControl숨김`으로 한 곳에서 정한다 |
| 8 | **숨긴 노치가 클릭을 가로챔** (Mission Control의 창 미리보기가 위쪽에 있다) | 숨기는 동안 `ignoresMouseEvents = true`, 호버·길게 누름·파일 드래그 감시는 중단 |
| 9 | **노치가 펼쳐진 채 Mission Control** | 접기를 먼저 끝낸 뒤 숨긴다. 타이머 숫자 입력 중이면 키 포커스를 돌려준다 (`releaseKeyFocus`) |
| 10 | **애니메이션 도중 상태가 또 바뀜** | 스프링 애니메이션은 중단 가능하고, 목표값(`hiddenAmount`)만 바꾼다 |
| 11 | **다중 디스플레이** | Mission Control은 디스플레이마다 창이 생길 것으로 보이지만 **미확인**. 안전하게 "어느 디스플레이든 Spaces Bar가 있으면 **모든 노치를 함께** 숨기고, 모두 없어지면 함께 복귀" |
| 12 | **Mission Control 중 디스플레이 연결·해제** | 새 패널은 숨긴 상태로 만들고, 복귀 때 함께 보인다 |
| 13 | **메모리 자동 최적화 재시작이 숨김 중에 일어남** | 재시작 직후 시작 확인(§2.2)이 숨김을 다시 판단한다. 재시작은 노치가 닫혀 있을 때만 하므로 Mission Control 중에는 거의 일어나지 않는다 |
| 14 | **창 이름이 OS 업데이트로 바뀜** | 판정 규칙을 한 곳에 모으고, 릴리스 전 신호표 점검(§2.5) |

### 2.5 시험 항목

| 시험 | 합격 기준 |
|---|---|
| ⌃↑, `open`, 트랙패드 제스처, 핫코너로 열고 닫기 20회 | 열릴 때마다 0.3초 안에 숨김 시작, 닫힐 때마다 복귀, 어긋남 0회 |
| 앱 Exposé, 바탕화면 보기, Stage Manager, 런치패드·앱 목록 | 숨지 않는다 |
| 열자마자 닫기(0.2~0.5초 간격) 20회 | 최종 상태가 실제와 같다 |
| 노치를 펼친 채 / 타이머 입력 중 / 채팅 글 쓰는 중 열기 | 접힌 뒤 숨고, 글은 보존, 복귀 뒤 정상 |
| 잠금·잠금 해제 직후 Mission Control | 알파가 어긋나지 않는다 |
| 알림이 숨김 중에 도착 | 복귀 뒤 보인다 |
| 이벤트 등록을 일부러 끈 빌드 | 3초 안전 점검으로 동작, 폴링 전환 |
| 자원: 평소 대기 CPU·깨어남·메모리 | 지금과 같다 (0.12~0.2%, 깨어남 초당 0~2) |
| **신호표 점검** (릴리스 전, 새 macOS마다) | §1.1의 표를 같은 방법으로 다시 기록해 규칙과 맞는지 확인 |

## 3. 다중 디스플레이

### 3.1 요구 정리와 용어 (2026-11-06 결정 반영)

| 요구 | 정리 |
|---|---|
| 노치를 보일 디스플레이 | 연결된 디스플레이 중 **하나** 또는 **모든 디스플레이**. **업데이트 후 기본값은 주 디스플레이에만 표시**하고, 다른 디스플레이는 설정에서 켠다 |
| 상호작용 | 길게 눌러 연 확장 화면은 **누른 디스플레이에만** 뜬다 |
| 상호작용의 결과 | 미디어 곡 변경, 트레이 파일, 상시 표시 숨김, **마지막으로 본 홈 페이지** 등은 **모든 디스플레이에 공유** |
| 디스플레이별 상시 표시 | 연결된 디스플레이마다 선택 (§3.4). 선택지에 **노치 없음**이 있다 |
| **노치 없음** | 그 디스플레이는 사실상 노치가 없는 것으로 본다. **모든 알림(일회성·상시·중요)과 모든 상호작용(호버·길게 누름·파일 끌기·확장)에서 제외**한다. 패널 자체를 만들지 않는다 |
| 대체 옵션 | 선택한 상시 표시가 비활성일 때 주 디스플레이의 상시 표시를 대신 보일지 (기본 **켬**) |
| 일회성 알림 범위 | 설정으로 **주 디스플레이만** / **노치를 켠 모든 디스플레이** 중 선택. "모든 디스플레이"는 "노치 없음"이 아닌 디스플레이만 뜻한다 |
| 중요한 알림 | 기본으로 노치를 켠 모든 디스플레이에 표시. 설정에서 끄거나 표시할 알림 종류를 추가할 수 있다 |

**용어**: **주 디스플레이** = 메뉴바가 있는 디스플레이(`NSScreen.screens.first`, 지금 코드의 `.main`). `NSScreen.main`은 키 창이 있는 디스플레이라 다르므로 **쓰지 않는다.** **노치를 켠 디스플레이** = 표시 대상으로 선택되었고 "노치 없음"이 아닌 디스플레이.

**"비활성"의 정의** (대체 옵션): 그 디스플레이에 선택한 상시 표시 항목의 **상시 표시 활동이 지금 존재하지 않는 상태**다. 예를 들어 서브 디스플레이를 "VPN"으로 선택했을 때 이 앱의 VPN 상시 표시는 `VPN 상시 표시 설정이 켜져 있고` **그리고** `VPN이 연결되어 있을 때`만 생긴다 (`NetworkMonitor`). 둘 중 하나라도 아니면 "비활성"이다.

### 3.2 구조 — 공유 모델 1개 + 디스플레이별 화면 상태 N개

지금은 `NotchController`(패널 1개) + `NotchViewModel`(화면 상태) + `ActivityCenter`(공유 상태)가 하나씩 있고, 화면 상태와 공유 상태가 `NotchViewModel`에 섞여 있다.

**공유 (이미 하나, 그대로 둔다)**: `ActivityCenter`(일회성 알림, 상시 표시 목록, 상시 표시 숨김 `persistentHidden`), 미디어·트레이·메모·채팅·타이머·일정·AI 사용량 저장소, 설정.

**디스플레이마다 따로 (새로 N개)**: 패널, 호스팅 뷰, `DisplayNotchState`(= 지금 `NotchViewModel`에서 화면 상태만): 노치 크기·물리 노치 여부, 확장 여부, 확장 페이지, 호버, 눌림, 스와이프, 파일 끌기, 채팅 크기.

```
NotchHub (1개)
 ├─ shared:   ActivityCenter, 저장소들, SharedNotchState(마지막으로 본 홈 페이지 등)
 ├─ displays: [DisplayKey: DisplayNotch]       // 노치를 켠 디스플레이만. DisplayNotch = 패널 + 호스팅 뷰 + DisplayNotchState + 컨트롤러
 ├─ expanded: DisplayKey?                       // 확장된 디스플레이는 최대 1개
 ├─ router:   AlertRouter                       // 알림이 어느 디스플레이에 뜰지 정한다 (§3.6)
 └─ visibility: PanelVisibility                 // 잠금·Mission Control의 합 ("노치 없음"은 패널이 없다)
```

**변경 범위** (현재 코드 기준): `NotchViewModel`을 쓰는 곳은 `NotchController`(44곳), `NotchRootView`(47곳), `AppDelegate`(37곳), `HomeView`(14곳), `TrayStore`(6곳), `LockScreenManager`·`CameraAndCalendar`(각 2곳), `TimerController`(흔들기 1곳)다. `displayTarget`은 `NotchGeometry`, `NotchController`, `LockScreenManager`, 설정 화면에서 쓴다. 대부분 이름 바꾸기 수준의 기계적 변경이고, 동작을 새로 정해야 하는 곳은 §3.5에 모았다.

**상시 표시 투영**: `vm.center.displayed`(`lockActivity ?? transient ?? topPersistent`) 등을 디스플레이별로 거르는 `ActivityFeed`를 둔다. `DisplayNotchState`가 `center` 대신 `feed`를 읽게 하면 나머지 화면 코드는 바뀌지 않는다 (§3.6).

### 3.3 디스플레이 식별과 설정 저장

| 항목 | 방법 |
|---|---|
| 식별 | `CGDisplayCreateUUIDFromDisplayID`의 UUID (이 Mac의 내장 디스플레이에서 값을 얻는 것은 확인). 연결을 껐다 켜도 같은 모니터는 같은 UUID이므로 설정이 유지될 것으로 보이나 외부 모니터에서는 **미확인** (§5.1에서 확인) |
| 표시 이름 | `NSScreen.localizedName` (이 Mac에서 `Built-in Retina Display` 확인). 같은 이름이 둘이면 "모니터 (2)"로 구분하고 화면 배치의 위치(왼쪽/오른쪽)를 함께 보인다 |
| 미러링 | 같은 화면을 복제하는 디스플레이는 **하나로 취급**한다 (`CGDisplayIsInMirrorSet`). **미확인** |
| 연결 해제 | 설정은 지우지 않고 보관한다. 선택된 디스플레이가 없으면 예전 규칙(노치 있는 화면 → 주 디스플레이)으로 대신 보이고, 다시 연결되면 원래대로 돌아온다 |
| 이전 | 예전 `displayTarget`(`builtIn`/`main`)은 **그 값 그대로 이어 받아 디스플레이 하나만** 선택한 상태로 옮긴다 (아래 저장 항목 표 참고). 새 설정은 모두 "다른 디스플레이는 꺼짐"이 기본이라 업데이트로 노치가 새로 생기는 디스플레이는 없다 |

**저장 항목** (`AppSettings`의 **`init`과 `reload()` 두 곳 모두**에서 읽는다):

| 키 | 값 | 기본값 |
|---|---|---|
| `notchDisplays` | `one:<UUID>` / `builtIn` / `main` / `all` | 이전 `displayTarget` 값 (신규 설치는 `main`) |
| `displayContent` | 사전 `UUID → 선택` (`all` / `kind:<이름>` / `notchOnly` / `none` / `followMain`) | 주 디스플레이 = `all`, 나머지 = `followMain` |
| `displayFallbackToMain` | Bool | **true** |
| `alertScope` | `main` / `all` | `main` (§6의 "남은 확인" 1번) |
| `criticalAlertsEnabled` | Bool | **true** |
| `criticalAlertAdded`, `criticalAlertRemoved` | 종류 이름 배열. **기본 목록과의 차이만** 저장 | 둘 다 비어 있음 |

`criticalAlert*`를 "기본 목록과의 차이"로 저장하는 이유: 나중에 기본 중요 알림이 늘거나 줄어도, 사용자가 직접 바꾼 것만 유지하고 나머지는 새 기본값을 따른다.

### 3.4 설정 화면

**설정 → 일반 → 표시 화면 (노치를 보일 디스플레이)** (지금의 `내장 / 주` 선택을 바꾼다)

- 목록: 연결된 디스플레이 전체 (이름, 해상도, "주 디스플레이" "내장" 표시) + **모든 디스플레이**.
- 연결 상태가 바뀌면 목록이 바로 갱신된다 (설정 창은 별도 프로세스이므로 거기서도 `didChangeScreenParameters`를 받는다).
- **다른 디스플레이에도 켜려면**: 그 디스플레이를 고르거나 "모든 디스플레이"를 고른 뒤, 아래 "디스플레이별 상시 표시"에서 "노치 없음"이 아닌 값을 둔다. "모든 디스플레이"에서 일부만 켜려면 나머지를 "노치 없음"으로 둔다.
- 연결된 디스플레이가 1개면 선택은 비활성화하고 "연결된 디스플레이가 1개입니다"를 작게 보인다.

**설정 → 상호작용 → 기본 → "디스플레이" 구역** (디스플레이가 2개 이상 연결된 때만 보인다. 1개면 숨김)

**① 디스플레이별 상시 표시** (연결된 디스플레이마다 한 줄. 이름과 주 디스플레이 표시)

| 선택 | 뜻 |
|---|---|
| **모든 상시 표시 컨텐츠** | 지금처럼 우선순위가 가장 높은 상시 표시를 보인다 |
| **개별 상시 표시 항목** | 미디어, 타이머, 다운로드, 에어드랍, AI 사용량, 충전(고정), 일정(고정), VPN, 핫스팟, 집중 모드(고정), 통화, 녹화 중 중에서 하나. 그 항목이 활성일 때만 보인다 |
| **노치만** | 선택한 상시 표시 없이 기본 노치(알림, 길게 눌러 여는 홈)만. 단 **중요한 알림은 예외** (§3.4의 ④) |
| **노치 없음** | 이 디스플레이에는 노치를 띄우지 않는다. 알림·상호작용 모두 제외 |
| **주 디스플레이의 설정을 따름** | 주 디스플레이의 선택을 그대로 쓴다 (주 디스플레이 줄에는 이 항목이 없다) |

- 기본값: 주 디스플레이 = "모든 상시 표시 컨텐츠", 나머지 = "주 디스플레이의 설정을 따름".
- **노치를 켠 디스플레이가 0개가 되는 선택은 막는다.** 마지막 하나는 "노치 없음"을 고를 수 없고(항목 비활성화) 이유를 작게 보인다.
- 개별 항목 중 그 기능의 상시 표시 설정이 꺼져 있는 것은 이름 옆에 "(설정에서 꺼짐)"을 보여, 왜 항상 대체 동작이 되는지 알 수 있게 한다.

**② 대체 옵션**

> ☑ 선택한 상시 표시가 비활성화인 경우 주 디스플레이의 상시 표시 컨텐츠를 표시
> <small>이 옵션을 끄면 선택한 상시 표시가 비활성화인 경우 기본 노치만 뜹니다.</small>

(문구는 요청하신 그대로. 기본값 켬)

예) 서브 디스플레이를 "VPN"으로 선택하고 VPN이 연결되지 않은 경우 → **켬**: 서브 디스플레이에 주 디스플레이의 상시 표시를 보인다. **끔**: 상시 표시 없이 기본 노치만 보인다.

**③ 일회성 알림 표시**: `주 디스플레이만` / `노치를 켠 모든 디스플레이` (기본: 주 디스플레이만). 주 디스플레이가 "노치 없음"이면 자동으로 "노치를 켠 모든 디스플레이"로 본다 (알림이 사라지지 않게).

**④ 중요한 알림**: 스위치 "중요한 알림은 노치를 켠 모든 디스플레이에 표시"(기본 켬) + "표시할 알림" 체크 목록 + "기본값으로 되돌리기". 목록의 기본 체크는 아래 표와 같고, 사용자는 기본 항목을 끄거나 다른 종류를 켤 수 있다.

| 알림 | 형태 | 기본 | 판단 이유 |
|---|---|---|---|
| **통화** (수신 카드, 통화 중) | 일회성 + 상시 | **켬** | 시간 안에 응답해야 한다 |
| **타이머 완료** | 일회성 | **켬** | 사용자가 맞춰 둔 알람이다 |
| **일정 알림** | 일회성 | **켬** | 시간에 맞춘 알림이다 |
| **배터리 부족**(저전력 경고) | 일회성 | **켬** | 곧 꺼진다. 충전 시작·완료는 해당 없음 |
| **화면 녹화 중** 표시 | 상시 | **켬** | 녹화 중임을 알리는 표시라 어느 화면을 보든 보여야 한다 (개인정보) |
| 화면 잠금 / 해제 | 별도 경로 | (목록 밖) | 잠금 중에는 주 디스플레이의 잠금 노치만 쓴다 (§3.5) |
| AI 에이전트 작업 완료, AI 채팅 답변 완료, 업데이트 완료 | 일회성 | 끔 | 놓쳐도 나중에 확인할 수 있다 |
| 다운로드·에어드랍 결과, 스크린샷 카드, 곡 변경, 블루투스·네트워크·VPN·집중 모드 전환, 충전 시작·완료 | 일회성 | 끔 | 다시 볼 수 있거나 즉시 필요하지 않다 |
| 볼륨·밝기·키보드 백라이트 HUD | 일회성 | 끔 | 사용자가 키를 누른 바로 그 순간의 반응이라 주 디스플레이만으로 충분하다 (원하면 켤 수 있다) |

- **중요 알림은 ③의 알림 범위와 ①의 상시 표시 선택보다 우선**한다. 예: 알림 범위가 "주 디스플레이만"이어도, 서브 디스플레이가 "VPN"이나 "노치만"이어도 통화·타이머 완료·일정·배터리 부족·녹화 중은 뜬다. 단 **"노치 없음"인 디스플레이에는 뜨지 않는다.**
- 목록의 한 줄은 **알림 하나(종류 + 형태)**다. 통화는 수신 카드와 통화 중 표시 둘 다, 화면 녹화는 녹화 중 표시(시작 알림 포함)에 적용하고, 타이머·일정·배터리 부족과 나머지 종류는 **일회성 알림에만** 적용한다. 그래서 "타이머 완료"를 켜도 실행 중인 타이머 표시가 다른 디스플레이로 따라가지는 않는다.
- "배터리 부족"은 같은 배터리 종류의 다른 알림(충전 시작·완료)과 구분해야 하므로 우선순위 값(`ActivityPriority.batteryLow`)으로 식별한다.

### 3.5 작동 규칙

| 상황 | 규칙 |
|---|---|
| **확장은 한 번에 1개** | 다른 디스플레이에서 길게 누르면, 먼저 열려 있던 디스플레이를 접고(애니메이션 없이 정리) 새 디스플레이를 연다. 타이머 입력·메모 편집·채팅 입력·카메라·파일 트레이 끌기가 모두 하나뿐인 객체라 동시에 열면 충돌한다 |
| **어느 디스플레이에서 열었나** | 길게 누른 디스플레이에만 확장 화면이 뜬다. 바깥 클릭으로 접는 판단도 그 디스플레이의 영역만 본다 |
| **마지막으로 본 홈 페이지** | **모든 디스플레이가 공유.** 접을 때와 페이지를 넘길 때 `SharedNotchState`에 쓰고, 다음에 어느 디스플레이에서 열든 거기서 시작한다. 요청하신 트레이 예시(주 디스플레이에서 파일을 넣고 닫은 뒤 다른 디스플레이에서 열면 같은 파일이 보임)가 이 규칙과 공유 저장소로 성립한다 |
| **일회성 알림** | `AlertRouter`가 정한 디스플레이에 같이 뜬다 (§3.6). 상세 카드를 눌러 처리하거나 위로 밀어 닫으면 **모든 디스플레이에서 함께 닫힌다** (알림은 하나뿐이다) |
| **상시 표시 숨김** (두 손가락 위로) | `ActivityCenter.persistentHidden`이 공유 상태이므로 모든 디스플레이에 함께 적용된다. 아래로 하면 함께 돌아온다 |
| **호버로 알림 타이머 멈춤** | 지금은 `center.paused`를 컨트롤러 하나가 정한다. 컨트롤러가 여러 개면 한 디스플레이에서 호버 중에 다른 디스플레이가 `false`로 덮어쓴다. **디스플레이별 호버를 모아 "하나라도 호버 중이면 멈춤"**으로 바꾼다 |
| **파일 끌기** | 파일이 들어오는 감지는 노치를 켠 디스플레이마다 따로 한다 (각 패널의 위쪽 영역). 끌기 시작 기준(`dragBaseline`)은 모든 컨트롤러가 같은 마우스 누름 이벤트로 갱신한다. 에어드랍·트레이↔AI 채팅 전환 막대도 그 디스플레이 안에서 동작한다 |
| **잠금 화면** | 잠금 노치 창은 지금처럼 1개만 쓴다 (주 디스플레이). 잠겨 있는 동안 **다른 디스플레이의 노치는 모두 숨긴다.** 다중 디스플레이의 잠금화면 동작은 **미확인**이라 1차는 주 디스플레이에만 둔다. 주 디스플레이가 "노치 없음"이면 잠금 노치도 쓰지 않는다 |
| **Mission Control** | §2.4의 11번: 어느 디스플레이든 감지되면 노치를 켠 디스플레이를 모두 숨기고 모두 함께 복귀 |
| **"노치 없음"인 디스플레이** | 패널이 없으므로 호버·눌림·파일 끌기·확장·알림 어느 것도 받지 않는다. 메뉴바 아이콘과 설정 창은 그대로 쓸 수 있다 |
| **디스플레이 연결·해제** | `didChangeScreenParameters`는 한 번의 변화에 여러 번 온다. **약 0.6초 모아서 한 번만** 처리한다 (§3.7 3번) |

### 3.6 디스플레이별 표시 결정 규칙

```
enabled(d)  = d가 notchDisplays로 선택됨  &&  choice[d] != none          // "노치 없음"은 여기서 빠진다 (패널·알림·상호작용 없음)

// 일회성 알림이 뜰 디스플레이
alertDisplays(a):
  if settings.criticalAlertsEnabled && a ∈ criticalAlerts:          return enabled 전부     // (종류, 형태) 단위로 판단
  if alertScope == all  ||  main ∉ enabled:                         return enabled 전부
  return [main]

// 디스플레이 d(enabled)의 상시 표시 목록
persistent(for d):
  choice = settings.content[d]
  if choice == followMain, d != main:  d, choice = main, settings.content[main]      // 한 번만 따라간다. 주 디스플레이가 followMain이면 all로 본다
  base = switch choice:
    notchOnly: []
    all:       center.orderedPersistent
    kind(k):   if let a = center.persistent[k]:  [a]
               // 선택한 항목이 지금 활성이 아님 → '비활성화'
               else if settings.fallbackToMain:  persistentOfMain()     // 주 디스플레이의 선택 결과를 한 번만 가져온다 (재귀 없음)
               else:                             []                      // 기본 노치만
  crit = criticalAlertsEnabled ? center.persistent.values.filter(kind ∈ {call, recording} 이고 목록에서 켜져 있음) : []   // 상시 형태가 중요한 것은 통화 중·녹화 중 둘뿐
  return (base ∪ crit) 를 settings.persistentOrder 순서로

displayed(for d) = center.lockActivity ?? 내게 온 transient ?? persistent(for d).first
```

- 무한 반복이 생기지 않는다: `followMain`은 한 번만 따라가고, 대체도 한 번만 한다. 주 디스플레이의 `kind(k)`가 비활성이어도 주 디스플레이는 자기 자신으로 대체하지 않고 빈 목록이 된다.
- 주 디스플레이가 "노치 없음"이면 `main ∉ enabled`이므로, "주 디스플레이만" 범위는 자동으로 "노치를 켠 모든 디스플레이"가 되고, `followMain`인 디스플레이는 주 디스플레이의 "노치 없음"을 따르지 않고 `all`로 본다 (노치를 켠 디스플레이가 사라지지 않게).
- 이 규칙은 순수 함수이므로 §5의 단위 시험으로 모든 조합(선택 5종 × 대체 켬/끔 × 활성/비활성 × 알림 범위 × 중요 알림 켬/끔 × "노치 없음"인 디스플레이)을 숫자로 확인한다.

### 3.7 일어날 수 있는 충돌·오류와 해결

| # | 문제 | 해결 |
|---|---|---|
| 1 | **두 디스플레이에서 동시에 확장** (타이머 입력·메모·채팅·카메라 충돌) | `NotchHub.expanded`로 1개만 허용. 다른 곳을 열면 먼저 접는다 |
| 2 | **알림 타이머가 호버 때문에 멈췄다 풀렸다 함** | 호버를 디스플레이별로 모아 합친다 (§3.5) |
| 3 | **연결·해제 때 패널이 여러 번 만들어졌다 사라져 깜빡임** | 0.6초 모아서 한 번 처리, UUID로 **차이만** 반영 (새로 생긴 것만 만들고, 없어진 것만 내리고, 나머지는 위치만 조정). 패널을 통째로 다시 만들지 않는다 |
| 4 | **선택한 디스플레이가 연결 해제** | 설정은 그대로 두고 예전 규칙(노치 있는 화면 → 주 디스플레이)으로 대신 표시. 다시 연결되면 복귀 |
| 5 | **덮개를 닫아(클램셸) 내장 디스플레이가 없어짐** | 4번과 같음. 노치가 없는 외부 디스플레이는 이미 있는 **가상 노치**(메뉴바 높이, 폭 190pt)로 그린다 |
| 6 | **같은 이름의 모니터 두 대** | UUID로 구분, 목록에는 번호와 화면 배치 위치를 함께 보인다 |
| 7 | **미러링** | 하나로 취급 (§3.3). **미확인**이므로 구현 때 확인한다 |
| 8 | **디스플레이 해상도·배열 변경, 메뉴바 높이 변화** | 변경 때마다 노치 사각형을 다시 계산 (지금도 `reposition`이 함) |
| 9 | **디스플레이 절전 중 그리기** | 절전 중인 디스플레이(`CGDisplayIsAsleep`)는 그리지 않고, 깨어날 때 다시 배치 |
| 10 | **잠금 화면과 패널 보임 다툼** | `PanelVisibility`가 잠금·Mission Control을 합쳐 한 곳에서 정한다 (§2.4의 7번) |
| 11 | **상시 표시 선택이 서로 순환** (A가 B를, B가 A를 따름) | `followMain`은 주 디스플레이만 가리킨다 (§3.6). 주 디스플레이는 따를 수 없다 |
| 12 | **채팅이 두 화면에 동시에 활성** (`ChatStore.visible`이 하나뿐) | 확장은 1개이므로 채팅 페이지도 1개. 확장이 안 된 디스플레이에는 페이지 뷰 자체가 만들어지지 않는다 |
| 13 | **파일 끌기 감지가 두 번 동작** | 각 컨트롤러가 자기 패널의 위쪽 영역에서만 판단하고, 확장된 쪽만 끌기 상태가 된다 |
| 14 | **설정 창(별도 프로세스)이 모르는 디스플레이** | 설정 창에서도 `NSScreen`으로 같은 UUID를 만든다. 설정 값은 기존 분산 알림(`settingsChanged`) 경로로 본 앱에 전달한다 |
| 15 | **개발용 명령·시험 도구가 첫 번째 디스플레이만 봄** (`notchctl`) | `display:<UUID 또는 번호>` 대상 지정을 추가한다 |
| 16 | **디스플레이마다 패널·뷰가 생겨 메모리·CPU 증가** | §3.8의 예산. "노치 없음"인 디스플레이에는 패널을 만들지 않는다 |
| 17 | **전체 화면 앱, Space 전환** | 패널의 `canJoinAllSpaces`·`fullScreenAuxiliary`는 지금과 같다. 다중 디스플레이의 전체 화면 동작은 **미확인** |
| 18 | **모든 디스플레이가 "노치 없음"** | 마지막 하나는 "노치 없음"을 고를 수 없게 막는다 (§3.4). 이미 그 상태로 저장되어 있으면(연결 변화로 생김) 주 디스플레이를 강제로 켠다 |
| 19 | **알림 범위가 "주 디스플레이만"인데 주 디스플레이가 "노치 없음"** | 알림이 사라지지 않도록 자동으로 "노치를 켠 모든 디스플레이"로 본다 (§3.6) |
| 20 | **중요 알림이 "노치만"·개별 항목 선택과 부딪침** | **중요 알림이 우선**한다고 규칙에 명시하고, 설정 문구에도 적는다. 원하지 않으면 스위치로 끈다 |
| 21 | **선택한 항목의 기능 설정이 꺼져 있어 항상 비활성** (예: VPN 상시 표시 꺼짐) | "비활성" 규칙 그대로 대체 옵션이 적용된다. 목록에 "(설정에서 꺼짐)"을 보여 원인을 알 수 있게 한다 |
| 22 | **일회성과 상시를 함께 내는 종류**(통화·녹화·타이머·에어드랍·다운로드) | 목록의 한 줄을 (종류 + 형태)로 정의해, 중요 알림이 상시 표시(실행 중 타이머, 다운로드 진행 등)까지 끌고 가지 않게 한다. 상시 형태가 중요한 것은 통화 중·녹화 중 둘뿐 |
| 23 | **앱 업데이트로 기본 중요 알림이 바뀜** | 사용자가 바꾼 차이만 저장하므로(§3.3) 직접 바꾼 것은 유지되고 나머지는 새 기본값을 따른다 |
| 24 | **알림이 도착했을 때 노치를 켠 디스플레이가 없음** (연결 변화 중) | 알림은 `ActivityCenter`에 남아 있다가 패널이 생기면 보인다. 표시 시간은 패널이 없는 동안 멈춘다 |

### 3.8 자원 예산

| 항목 | 기준 |
|---|---|
| 디스플레이 1개 | 지금과 같다 (메모리 약 18MB, 대기 CPU 0.12~0.2%, 깨어남 초당 0~2) |
| 디스플레이 추가 1개 | 메모리 **+6MB 이하**, 대기 CPU **+0.05% 이하**, 새 타이머·폴링 없음 |
| "노치 없음"인 디스플레이 | 패널·호스팅 뷰를 만들지 않는다 (추가 비용 0) |
| 디스플레이 연결·해제 20회 반복 | 누수 0건, 메모리가 연결 횟수에 비례해 늘지 않는다 (패널은 내릴 때 `contentView = nil`로 내용을 떼어 낸다 — 잠금 노치 창이 이미 쓰는 방식) |
| Mission Control 감지 | §2.5의 자원 기준 |

## 5. 시험 계획

| 방법 | 용도 | 상태 |
|---|---|---|
| **단위 시험** (`--display-probe`, 개발 빌드): 가짜 디스플레이 목록과 설정을 주고 §3.6의 결과를 출력 | 상시 표시·알림 대상 결정의 모든 조합, 이전(마이그레이션), UUID 처리 | 만들 수 있음 |
| **가짜 두 번째 패널** (`DMN_FAKE_DISPLAYS=2`, 개발 빌드): 같은 화면에 디스플레이 하나를 더 흉내 내어 패널 2개를 만든다 | 확장 1개 규칙, 호버 합치기, 알림 공유, 메모리·CPU 증가량(§3.8). **외부 디스플레이 없이** 먼저 확인할 수 있다 | 만들 수 있음 |
| **가상 디스플레이** (`CGVirtualDisplay`, 비공개 API): 진짜 두 번째 `NSScreen`을 만든다 | 연결·해제 흉내, 배열 변경 | 클래스 4개가 이 Mac에 있는 것은 확인. **실제로 만들어 보지는 않았다** |
| **실제 외부 모니터** (보유, 현재 연결 안 됨) | 가상 노치(노치 없는 화면), 미러링, 잠금화면, 전체 화면 앱, 덮개 닫기, 절전 복귀, Mission Control | 연결 후 §5.1 |

### 5.2 구현 뒤 실제 모니터 시험 목록 (D3 이후)

1. 주 디스플레이만 켠 기본 상태에서 업데이트 직후 노치 위치가 그대로인가.
2. "모든 디스플레이"를 켜고 서브 디스플레이를 "VPN"으로 고른 뒤 VPN을 연결·해제하며 대체 옵션 켬/끔 동작 확인.
3. 서브 디스플레이를 "노치 없음"으로 바꾸면 노치·알림·길게 누름·파일 끌기가 모두 사라지는가. 마지막 하나는 고를 수 없는가.
4. 알림 범위 "주 디스플레이만"에서 볼륨 HUD는 주 디스플레이에만, 타이머 완료·통화는 노치를 켠 모든 디스플레이에 뜨는가. 중요 알림 스위치를 끄면 주 디스플레이에만 뜨는가.
5. 주 디스플레이에서 미디어 팝업을 연 뒤 곡을 바꾸고 접으면 서브 디스플레이의 컴팩트 표시에도 곡이 바뀌는가. 서브에서 길게 눌렀을 때 주가 접히는가.
6. 주 디스플레이에서 트레이에 파일을 넣고 접은 뒤 서브에서 길게 눌러 열면 같은 파일이 마지막 페이지(트레이)로 보이는가.
7. 두 손가락 위로 상시 표시를 숨기면 두 디스플레이 모두 숨는가.
8. Mission Control에서 두 디스플레이의 노치가 함께 줄어들며 사라지고 끝나면 함께 돌아오는가.
9. 케이블 뽑기·꽂기, 덮개 닫기, 절전 복귀를 20회 반복해도 패널이 깜빡이거나 남지 않고 메모리가 늘지 않는가.
10. 잠금·잠금 해제 후 두 디스플레이의 노치가 정상인가.

## 6. 결정된 사항 (2026-11-06)과 남은 확인

**결정됨**

| # | 항목 | 결정 |
|---|---|---|
| 1 | "선택한 상시 표시가 비활성화인 경우" | 개별 상시 표시 항목(예: VPN)을 선택했을 때 그 항목이 활성이 아니면 비활성. 대체 옵션 켬이면 주 디스플레이의 상시 표시를, 끔이면 기본 노치만 (§3.1, §3.4) |
| 2 | 일회성 알림 범위 | 설정 옵션 `주 디스플레이만` / `노치를 켠 모든 디스플레이`. "모든"은 "노치 없음"이 아닌 디스플레이만 |
| 3 | 마지막으로 본 홈 페이지 | 모든 디스플레이가 공유 |
| 4 | 업데이트 후 기본값 | 주 디스플레이에만 표시. 다른 디스플레이는 설정에서 켠다 |
| 5 | 대체 옵션 기본값 | 켬 |
| 6 | 중요한 알림 | 제가 판단한 기본 5종(통화, 타이머 완료, 일정, 배터리 부족, 화면 녹화 중)을 기본으로 모든 노치에 표시. 설정에서 끄거나 종류를 추가 |
| 7 | 외부 디스플레이 | 보유, 현재 연결 안 됨. 연결 뒤 빌드를 시작하며 §5.1부터 한다 |
| 8 | "노치 없음" | 모든 알림·상호작용에서 제외, 패널을 만들지 않는다 |

**남은 확인** (제가 고른 값이므로, 다르면 알려 주세요)

1. **일회성 알림 범위의 기본값**을 "주 디스플레이만"으로 했다. 다른 디스플레이를 켜도 중요한 알림이 아니면 주 디스플레이에만 뜬다는 뜻이다. 다른 디스플레이를 켰을 때 알림도 함께 뜨기를 원하시면 "노치를 켠 모든 디스플레이"가 기본이 되도록 바꾼다.
2. **업데이트 직후의 노치 위치**: 기존에 "내장 화면"을 골랐던 사용자는 그 값을 그대로 이어 받는다. 외부 모니터가 주 디스플레이이면서 내장을 골랐던 경우에만 "주 디스플레이에만"과 다른 결과가 나온다. 이때도 노치가 갑자기 옮겨 가지 않도록 기존 선택을 유지하는 것이 안전하다고 판단했다.
3. **중요 알림 기본 5종**의 구성. 특히 "화면 녹화 중"은 알림이라기보다 상시 표시이지만, 녹화 중임을 어느 화면에서든 알려야 한다고 보아 넣었다.

**A.1 디스플레이 정보** — 이름, UUID, 주 디스플레이, 노치 높이, 미러 여부, 별도 Space 설정

**A.2 창 변화 기록** — Mission Control·앱 Exposé 등을 열고 닫는 동안 `WindowManager`·`Dock` 창의 변화를 ms 단위로 기록 (창 위치 `@x,y`로 디스플레이를 구분)

```bash
swiftc -O winrec.swift -o winrec && ./winrec 30
```

```swift
// 사용법: swiftc -O winrec.swift -o winrec && ./winrec 30
// Mission Control 등을 열고 닫는 동안 WindowManager·Dock의 창 변화를 ms 단위로 기록한다.
import AppKit
import CoreGraphics
setvbuf(stdout, nil, _IOLBF, 0)
let start = Date()
func ms() -> Int { Int(Date().timeIntervalSince(start) * 1000) }
for s in NSScreen.screens {
    let id = s.deviceDescription[NSDeviceDescriptionKey("NSScreenNumber")] as? CGDirectDisplayID ?? 0
    print("SCREEN", s.localizedName, "frame", s.frame, "notchInset", s.safeAreaInsets.top, "id", id)
}
var last = ""
func state() -> String {
    guard let list = CGWindowListCopyWindowInfo([.optionOnScreenOnly], kCGNullWindowID) as? [[String: Any]] else { return "" }
    var rows: [String] = []
    for w in list {
        let owner = w[kCGWindowOwnerName as String] as? String ?? ""
        guard owner == "WindowManager" || owner == "Dock" else { continue }
        let name = w[kCGWindowName as String] as? String ?? ""
        if owner == "Dock" && name.isEmpty { continue }
        let b = w[kCGWindowBounds as String] as? [String: CGFloat] ?? [:]
        rows.append(String(format: "%@/%@/L%d/%.0fx%.0f@%.0f,%.0f", owner, name.isEmpty ? "-" : name, w[kCGWindowLayer as String] as? Int ?? 0,
                           b["Width"] ?? 0, b["Height"] ?? 0, b["X"] ?? 0, b["Y"] ?? 0))
    }
    return rows.sorted().joined(separator: "\n      ")
}
Timer.scheduledTimer(withTimeInterval: 0.05, repeats: true) { _ in
    let s = state(); if s != last { print(String(format: "%6d ms", ms()), s.isEmpty ? "(none)" : "\n      " + s); last = s }
}
Timer.scheduledTimer(withTimeInterval: Double(CommandLine.arguments.dropFirst().first ?? "30") ?? 30, repeats: false) { _ in exit(0) }
RunLoop.main.run()
```

**A.3 창 서버 이벤트 기록** — 비공개 이벤트 번호가 다중 디스플레이에서도 같은지 확인 (§1.4). 이벤트는 앱 실행 루프에서만 오므로 도구 안에서 `NSApplication.run`을 돌린다

```swift
// 사용법: swiftc -O eventprobe.swift -o eventprobe && ./eventprobe 30
// 창 서버(SkyLight) 이벤트 번호 0~1999를 모두 등록하고, 오는 것을 번호와 함께 출력한다 (비공개 API, 시험용).
import AppKit
setvbuf(stdout, nil, _IOLBF, 0)
typealias Proc = @convention(c) (UInt32, UnsafeMutableRawPointer?, UInt32, UnsafeMutableRawPointer?) -> Void
typealias RegFn = @convention(c) (Proc, UInt32, UnsafeMutableRawPointer?) -> Int32
guard let h = dlopen("/System/Library/PrivateFrameworks/SkyLight.framework/SkyLight", RTLD_NOW),
      let reg = dlsym(h, "CGSRegisterNotifyProc") else { print("SkyLight 심볼 없음"); exit(1) }
let start = Date()
let callback: Proc = { type, _, _, _ in print(String(format: "%6d ms  event %d", Int(Date().timeIntervalSince(start) * 1000), type)) }
var ok = 0
for t in 0..<2000 where unsafeBitCast(reg, to: RegFn.self)(callback, UInt32(t), nil) == 0 { ok += 1 }
print("등록된 번호:", ok)
Timer.scheduledTimer(withTimeInterval: Double(CommandLine.arguments.dropFirst().first ?? "30") ?? 30, repeats: false) { _ in exit(0) }
let app = NSApplication.shared; app.setActivationPolicy(.prohibited); app.run()   // 이벤트는 앱 실행 루프에서만 온다
```
