# 얼굴 잠금 해제 — 보안·개인정보 설계 가이드라인

상태: **설계 문서 (미구현)**. 이 문서의 "게이트"를 통과하기 전에는 기능을 만들거나 배포하지 않는다.
이 기능은 맥 로그인 비밀번호를 다루므로, 편의보다 **유출되지 않는 것**이 항상 우선한다.

---

## 0. 한 줄 원칙

1. **잠겨 있는 동안에만** 켜지고, 잠금이 풀리면 **프로세스째 사라진다.**
2. 얼굴 사진은 **어디에도 저장하지 않는다.** 얼굴 수치(임베딩)와 비밀번호는 **키체인 밖으로 나가지 않는다.**
3. **네트워크를 쓰지 않는다.** 이 기능이 있는 코드는 네트워크 API를 부를 수 없다.
4. **기본값은 꺼짐.** 켜려면 비밀번호를 다시 입력하고 동의한다.
5. 이 기능은 **편의 기능**이며 Face ID 같은 보안 수단이 아님을 화면과 문서에 분명히 적는다.

## 1. 목적 제한 (잠금 해제 외 사용 금지)

- 얼굴 인식·카메라·모델은 **별도 도우미 프로세스**(`--face-unlock`, 기존 `--imgtool`·`--usage-fetch`와 같은 방식)에서만 돈다. 본 앱은 카메라 프레임·얼굴 수치·비밀번호를 **받지도 못한다.**
- 본 앱이 아는 것은 "일치했다 / 아니다 / 꺼짐" 한 가지 결과뿐이다. 홈 카메라(거울) 기능과 **카메라 세션·코드를 공유하지 않는다.**
- 다른 기능(메모 보호, 자리 비움 잠금 등)이 얼굴 인식을 재사용하는 것은 **금지**한다. 필요하면 별도 설계·별도 동의를 거친다.
- 코드 구조: 얼굴 기능은 전용 폴더 `Features/FaceUnlock/` 안에 두고, 다른 폴더가 그 안의 타입을 참조하지 못하게 한다(코드 리뷰 체크 항목).

## 2. 생명주기 — 잠겼을 때만 활성

| 시점 | 동작 |
|---|---|
| 평소(잠금 해제 상태) | 도우미 프로세스 **없음.** 카메라·모델 메모리 0. 본 앱 자원은 기존과 동일 |
| 화면 잠금 감지 | 이미 쓰는 잠금 신호(`screenIsLocked`)로 도우미를 띄움. 켜기 전에 **정말 잠겼는지** 세션 상태(`CGSessionCopyCurrentDictionary`의 잠금 키)로 한 번 더 확인 |
| 잠금 중 | 사용자 입력·덮개 열림·깨움 때만 카메라 시작. 화면 보호기 동안 계속 돌리지 않음 |
| 일치 | 비밀번호 입력 1회 → 도우미 즉시 종료 |
| 잠금 해제(어떤 방법이든) | 도우미 **즉시 종료** + 안전장치(감시 타이머)가 3초 안에 확인. 종료 못 하면 강제 종료 |
| 잠금 상태를 알 수 없음 | **꺼진 것으로 간주** (안전한 쪽으로 실패) |

- 카메라는 **저속(초당 5~10장)** 으로, 얼굴이 없으면 **30초 뒤 자동 중지**하고 다시 입력이 있을 때까지 쉰다(배터리·노출 시간 최소화).
- 자원 목표: **본 앱 메모리 증가 0.5MB 이하, 잠금 해제 상태 CPU 변화 없음.** 도우미는 잠금 중에만 일시적으로 쓰고 종료와 함께 전부 반환한다(수치는 시제품에서 측정해 문서에 기록).

## 3. 저장 데이터와 위치

| 데이터 | 저장 | 하지 않는 것 |
|---|---|---|
| 얼굴 수치(임베딩, 등록 샘플 여러 개) | 암호화해 **키체인에만** 저장 | 파일·UserDefaults·로그·클립보드에 쓰기 |
| 맥 로그인 비밀번호 | 키체인 항목, 접근 허용 앱을 **이 앱 서명 하나로 제한** | "모든 앱 허용", 환경 변수·실행 인자·클립보드·로그 |
| 카메라 프레임 | **메모리에만**, 처리 후 즉시 해제·0으로 덮어씀 | 디스크 저장, 캡처 이미지, 디버그 덤프(개발 빌드 포함) |
| 일치 점수 | 판정에만 쓰고 버림 | 기록·통계·전송 |

- 키체인 항목은 **이 기기 전용**(iCloud 동기화·백업 제외)이어야 한다. 잠금 중에도 읽어야 하므로 "첫 잠금 해제 이후" 접근 등급을 쓴다.
- 비밀번호는 Swift `String`으로 다루지 않는다(메모리를 지울 수 없음). `Data`/바이트 버퍼로 받아 쓰고 바로 0으로 덮는다.
- 얼굴 수치도 **생체 정보의 비밀 값**으로 취급한다. 수치만 있어도 사람을 식별할 수 있고 일부는 복원될 수 있다.
- ⚠️ **검증 필요:** 보안 하드웨어(Secure Enclave) 키와 데이터 보호 키체인은 Apple 개발자 서명이 필요할 가능성이 크다. 현재 이 앱은 애드혹 서명이다 → 게이트 A 참고.

## 4. 인증 절차 보안

**일치 판정**
- 한 장이 아니라 **연속 여러 장(예: 8장 중 6장)** 이 기준 이상이어야 하고, 기준은 **보수적으로**(오인식보다 거부가 낫다) 시작한다.
- 눈을 뜨고 카메라를 보는 상태만 인정한다(Vision 얼굴 랜드마크). 잠든 사람의 얼굴로 풀리지 않게 한다.
- **생체 확인(속이기 방어):** 2D 카메라라서 사진·영상에 약하다. 기본을 **강(머리 방향 바꾸기·눈 깜빡임 같은 능동 확인)** 으로 하고, 약화·끄기는 사용자가 위험 문구를 읽고 직접 선택하게 한다. 사진·화면 영상으로 속이기 시험을 통과하지 못하면 출시하지 않는다.
- **카메라 출처 제한:** 내장 카메라만 허용. 외부·가상 카메라(OBS 등)·연속성 카메라는 거부한다(영상 주입 방어).

**실패 처리**
- 연속 실패 5회 → 얼굴 잠금 해제를 **잠그고 비밀번호 입력을 요구**한다(비밀번호를 직접 입력해 풀면 다시 사용 가능).
- 비밀번호 자동 입력은 **한 번만** 시도한다. 틀렸으면 즉시 중단하고 저장된 비밀번호를 **무효화**한다(계정 잠김 방지).
- 재시작 직후, 24시간 이상 사용하지 않았을 때, 비밀번호를 바꿨을 때는 **얼굴로 못 풀게** 하고 한 번 비밀번호로 푼 뒤에만 다시 켠다. (FileVault 부팅 직후에는 어차피 비밀번호가 필요하다.)

## 5. 외부 호출·변조 방어 (가장 중요)

- 이 앱의 개발용 명령 채널은 보낸 쪽을 확인할 수 없는 분산 알림이다. **얼굴 잠금 해제는 그 채널·실행 인자·환경 변수·파일로 절대 시작·제어되지 않는다.**
- 도우미는 **본 앱이 직접 띄운 경우에만** 동작한다(부모 프로세스와 코드 서명 확인). 다른 프로그램이 `--face-unlock`을 흉내 내 실행해도 비밀번호가 나오지 않는다. (키체인의 접근 허용 앱 제한이 2차 방어선.)
- 도우미는 **외부 입력을 받지 않는다.** 부모와의 통신은 일방향 결과 통지(일치/불일치)만 허용한다.
- 비밀번호 입력은 **도우미 안에서, 일치 판정 직후, 잠금 상태가 확인된 때만** 한다. 입력은 합성 키 이벤트로만 하고 클립보드를 거치지 않는다.

## 6. 유출 방지 (코드 규칙)

- 얼굴 기능 코드에서 **네트워크 API(URLSession, 소켓 등) 사용 금지**, 외부 로그 전송 금지. 코드 리뷰와 빌드 검사로 확인한다.
- 프레임·수치·점수·비밀번호를 **로그·크래시 리포트·진단 출력에 넣지 않는다.** 개발 빌드도 동일(이 앱에서 개발용 진단이 Wi-Fi 이름을 파일에 남기던 전례가 있어, 진단 출력은 허용 목록 방식으로만 만든다).
- 인식 모델은 **앱에 포함해 배포**하고 실행 중 내려받지 않는다. 출처·라이선스·해시를 기록하고 해시로 고정한다.
- 테스트용 데이터(내 얼굴 수치, 시험 비밀번호)는 저장소·릴리스·스크린샷에 **절대 포함하지 않는다.** 시험 후 키체인 항목과 임시 파일을 삭제한다.

## 7. 업데이트·배포 위험 (자동 업데이트 + 비밀번호 보관)

이 앱은 자동 업데이트를 하므로, **저장소 계정이 탈취되어 악성 업데이트가 배포되면 보관된 비밀번호가 위험해진다.** 그래서:

- 얼굴 기능이 포함된 업데이트는 **자동 설치하지 않고** 사용자 확인을 받는다. 기능이 꺼져 있으면(기본) 비밀번호는 저장되지 않는다.
- 업데이트 검증에 **서명 팀 ID 고정**을 추가한다(현재는 서명·번들 ID·버전 확인). → 게이트 A 필요.
- 저장소 계정 2단계 인증, 서명된 태그, 릴리스 해시 공개를 필수로 한다.

## 8. 데이터 수명 주기

- **등록:** 설명 화면 → 동의 → 비밀번호 재입력(맥 인증) → 카메라로 여러 각도 등록. 등록 중에도 사진은 저장하지 않는다.
- **상태 표시:** 설정에 "등록됨/안 됨", 마지막 사용 시각만 표시(점수·이미지 없음).
- **삭제:** 설정의 "얼굴 데이터와 저장된 비밀번호 모두 삭제" 한 번으로 키체인 항목을 지운다. 앱을 지워도 키체인에 남을 수 있으므로 **삭제 안내를 설치 문서에 적는다.**
- 얼굴 기능을 끄면 **즉시 키체인 항목을 삭제**한다(끄기 = 삭제).
- 백업(Time Machine·iCloud)에 포함되지 않아야 한다.

## 9. 위협 모델 요약

| 위협 | 대응 | 남는 위험 |
|---|---|---|
| 사진·영상으로 속이기 | 능동 생체 확인, 내장 카메라만, 연속 일치 | 정교한 영상은 뚫릴 수 있음(2D 한계) — 문서에 명시 |
| 쌍둥이·닮은 사람 | 보수적 기준, 실패 5회 잠금 | 완전 방어 불가 |
| 잠든 사람·강제로 얼굴을 대는 경우 | 눈 뜸·시선 확인 | 의식 있는 강제는 방어 불가 |
| 다른 프로그램이 도우미 흉내 | 부모·서명 확인, 키체인 접근 제한, 외부 입력 없음 | 같은 계정의 악성코드가 키체인 승인을 속이는 경우 |
| 악성 업데이트 | 업데이트 확인, 팀 ID 고정, 계정 보호 | 개발자 환경 침해 |
| 디스크·백업에서 데이터 추출 | 키체인에만 저장, 이 기기 전용, 백업 제외 | 기기 잠금 해제 상태의 물리 접근 |
| 로그·크래시·진단으로 유출 | 기록 금지, 허용 목록 진단 | — |
| 계정 잠김(비밀번호 오입력) | 1회 시도, 즉시 무효화 | — |

## 10. 게이트와 단계

**게이트 0 — 실현 가능성 확인 (코드 작성 전, 실패하면 중단)**
- 잠금 화면에서 **카메라를 쓸 수 있는가?**
- 잠금 화면에 **비밀번호를 합성 입력으로 넣을 수 있는가?** 어떤 권한·서명이 필요한가?
- 두 질문 모두 이 문서 작성 시점에 **확인하지 못했다.** 작은 시제품으로 확인하되, 이 단계에서는 실제 비밀번호를 쓰지 않는다(시험용 계정 사용).

**게이트 A — 서명 (출시 전 필수)**
- Apple 개발자 프로그램 가입, Developer ID 서명 + 공증 + 하드닝 런타임. 비밀번호를 맡기는 앱은 애드혹 서명으로 배포하지 않는다.

**단계**
1. 시제품(게이트 0): 카메라·입력 가능 여부, 얼굴 모델 후보와 라이선스·크기 조사.
2. 정확도·속이기 시험: 본인 얼굴로 오거부율, 사진·화면 영상 공격으로 오수락을 측정하고 결과를 기록.
3. 강화 구현: 위 1~8장 규칙 적용, 도우미 프로세스 분리, 자원 목표 측정.
4. 보안 점검: 6장 코드 규칙 전수 검사, 외부 호출 시도(다른 프로그램이 도우미를 흉내 내는 시험), 키체인 접근 시험.
5. 시험 배포: "실험 기능"으로 표시, 기본 꺼짐, 동의 화면 포함.

## 11. 인수 시험 (자원·보안)

- 잠금/해제 50회 반복: 매번 도우미가 종료되는지, 잠금 해제 상태 본 앱 메모리·CPU가 기능 추가 전과 같은지, 누수 0.
- 잠금 해제 상태에서 카메라 사용 표시(녹색 점)가 **꺼져 있는지** 확인.
- 네트워크 감시: 잠금 중 도우미가 외부와 **통신하지 않는지** 확인.
- 로그·크래시·임시 폴더에서 프레임·수치·비밀번호가 **없는지** 검색.
- 다른 프로세스가 도우미를 실행하거나 알림을 보내도 **비밀번호 입력이 일어나지 않는지** 시험.
- 속이기 시험: 사진·영상으로 해제가 안 되는지(강 모드).
- 끄기·삭제 후 키체인에 항목이 **남지 않는지** 확인.

## 12. 법적·정책 메모

- 얼굴 정보는 민감한 생체 정보다. 기기 안에서만 처리·저장하고 외부로 보내지 않으며, 사용자가 언제든 삭제할 수 있게 하는 것이 기본 방침이다.
- 개인정보 관련 법규(국가별 요건)는 배포 범위에 따라 다르다. 공개 배포 전에 별도로 검토한다(이 문서는 법률 자문이 아니다).
