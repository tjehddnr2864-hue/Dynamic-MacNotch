# 노치 AI 채팅 — 설계 기록

작성: 2026-11-05 · 1.3.0에서 구현됨

> 첨부 파일과 출력 형식은 [CHAT_ATTACH_GUIDELINE.md](CHAT_ATTACH_GUIDELINE.md)를 보세요 (1.4.0). 구현 전에 쓴 설계 문서입니다. 아래 일부는 구현하면서 바뀌었고, §7의 "흐름 변경"과 "공통 프롬프트" 항목이 앞선 내용보다 우선합니다. 실제 동작과 개인정보 설명은 README를 기준으로 하세요.

노치 홈에서 Claude 또는 GPT에게 질문하고, 답변을 노치에 스트리밍으로 보여 주는 기능의 설계 기준이다.

---

## 0. 결론

- **가능하다.** 앱이 이미 가진 부품(홈 페이지, 메모의 입력 칸, 상세 알림, 별도 설정 프로세스, 임시 네트워크 세션)으로 대부분 만들 수 있다.
- **월정액 구독(Claude Pro/Max, ChatGPT 구독)의 로그인을 앱이 직접 쓰는 방식은 지원하지 않는다.** 기본 경로는 **각 회사의 API 키**이고, API 사용량은 구독과 별도로 과금된다 (§2).
- 설정에서 **서비스(Claude/GPT)와 서비스별 모델을 따로 지정**한다 (§2.4).
- Swift에는 두 회사의 공식 SDK가 없으므로 `URLSession`으로 HTTP(SSE 스트리밍)를 직접 호출한다. 재시도·취소·오류 처리를 직접 만들어야 한다.
- 이 앱의 핵심 지표(대기 CPU 0.2%, 메모리 17MB)가 깨지지 않게 하는 것이 설계의 제1 제약이다 (§6).

## 2. 인증 — 가장 중요한 결정

### 2.1 API 키만 지원한다
- Anthropic은 Claude 무료·Pro·Max **구독 로그인(OAuth) 토큰을 서드파티 앱에서 쓰는 것을 약관으로 금지**하고 API 키를 정식 경로로 안내한다 (2026-02 문서 개정이 보도됨. 이 내용은 2차 보도로 확인한 것이라, 구현 전에 Anthropic 공식 약관 원문을 직접 확인한다).
- ChatGPT 구독 로그인을 서드파티가 쓰는 것의 허용 여부는 **확인하지 못했다.** API 키 방식이면 이 문제를 피한다.
- 이미 있는 "AI 사용량" 기능은 웹 로그인으로 **사용량 페이지를 읽기만** 한다. 채팅과 성격이 다르므로 같은 방식으로 확장하지 않는다.

### 2.2 키 저장
- 현재 앱은 키체인을 쓰지 않는다 (`SecItem` 사용 0건). 이 기능이 첫 사용처다.
- **키체인(Generic Password)에 저장**한다. `UserDefaults`(plist 평문)에는 절대 저장하지 않는다.
- 설정 창은 별도 도우미 프로세스지만 본 앱과 같은 실행 파일·서명이라 같은 키체인 항목에 접근할 수 있다. 키 입력 칸은 `SecureField`, 저장 후에는 `sk-…끝4자리`처럼 마스킹한다.
- 앱은 ad-hoc 서명이다. `build.sh`가 지정 요구사항을 번들 ID로 고정해 두었으므로 **업데이트 후에도 키체인 접근이 유지될 가능성이 높지만, 실제로 확인하지 않았다.** → 시험 항목에 넣는다 (§8).
- 키를 로그·오류 메시지·크래시 정보·릴리스 노트에 남기지 않는다. 오류 표시에는 HTTP 상태와 종류만 쓴다.

### 2.3 연결 테스트
- 설정에 "연결 테스트" 버튼: 짧은 요청 1회로 키·모델 ID를 검증하고 결과(성공/401/404 등)만 보여 준다.

### 2.4 설정 화면: 서비스·모델 지정

| 서비스(연결 방식) | 인증 | 모델 칸 | 비고 |
|---|---|---|---|
| Claude · API 키 | 키체인의 Anthropic 키 | 프리셋 메뉴(`claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`) + 직접 입력 | 기본 경로 |
| GPT · API 키 | 키체인의 OpenAI 키 | 직접 입력 (프리셋 없음) | 최신 모델명을 코드에 박지 않는다. 잘못된 이름은 연결 테스트의 404로 알려 준다 |

- 서비스를 고르는 항목 하나와, **서비스마다 따로 저장하는 모델 칸**을 둔다. 서비스를 바꿔도 각 서비스의 마지막 모델이 유지된다.
- 저장 키 예: `chatService`, `chatModelClaudeAPI`, `chatModelOpenAI`. 키 자체는 설정이 아니라 키체인에 둔다.
- 설정 창은 별도 프로세스이므로 기존 방식(분산 알림 → `reload()`)으로 본 앱에 즉시 반영한다. `AppSettings`는 값을 `init`과 `reload()` 두 곳에서 읽으므로 **두 곳 모두** 추가해야 한다.
- 서비스를 바꾸면 진행 중인 응답은 취소하고 새 대화를 시작한다. (대화 기록은 역할+텍스트의 공통 형식이라 옮길 수는 있지만, 서비스마다 답변 성향이 달라 새 대화가 단순하다.)
- 선택 사항: "모델 목록 가져오기" 버튼(두 회사 모두 `GET /v1/models` 제공). 키 검증을 겸한다.

## 4. API 설계

### 4.1 공급자 추상화
공통 인터페이스 하나에 구현 둘.

```
ChatProvider.stream(history, onEvent)   // onEvent: .delta(String) / .done(reason) / .failed(kind)
```

- SSE 줄 파서는 하나만 만든다 (`event:` / `data:` 줄 단위, `URLSession.bytes(for:)` 로 읽기).
- 취소는 `Task.cancel()` 한 곳. 중지 버튼·페이지 닫기·새 대화·잠금이 모두 같은 경로로 취소한다.
- 모델 ID는 **설정에서 직접 입력**하게 하고 프리셋을 함께 둔다. 모델이 바뀌어도 앱 업데이트가 필요 없게 한다.

### 4.2 Claude (Anthropic Messages API)
- `POST https://api.anthropic.com/v1/messages`, 헤더 `x-api-key`, `anthropic-version`, `content-type: application/json`, 본문에 `"stream": true`.
- `anthropic-version` 값은 현재 문서의 값을 쓴다 (문서 예시 기준 `2026-10-21`).
- 화면에 쓰는 이벤트는 `content_block_delta`의 `text_delta`. `message_delta.stop_reason`으로 종료 사유를 본다.
- 재시도: 429·500·529만 지수 백오프(최대 2회). 400·401·403·404·413은 재시도하지 않고 바로 오류 표시.
- `stop_reason == "refusal"`이면 "이 질문에는 답할 수 없습니다"로 표시한다. 필요하면 서버 쪽 `fallbacks` 옵션을 검토한다.
- 모델 프리셋(참고 가격, 100만 토큰당 입력/출력):

| 프리셋 | 모델 ID | 가격 | 메모 |
|---|---|---|---|
| 빠름 | `claude-haiku-5-5` | $0.10 / $0.50 | 노치 짧은 Q&A에 적합 |
| 균형 | `claude-sonnet-5-5` | $2 / $10 | |
| 고성능 | `claude-opus-5-5` | $4 / $20 | 생각을 끌 수 없고 기본 effort가 `medium`이라 응답이 느리고 출력 토큰이 늘 수 있음 |

- 생각 내용은 기본으로 비어서 오므로, 첫 글자가 나오기 전에는 "생각 중…" 표시를 둔다.
- 시스템 프롬프트로 "노치 작은 화면에 표시되므로 짧고 간결하게"를 지시하고, `max_tokens`는 1024~2048로 시작한다.
- 질문 1회 비용 감: 입력 500 + 출력 500 토큰이면 Haiku 약 $0.0003, Opus 5.5 약 $0.012 (생각 토큰은 출력으로 과금되어 더 늘 수 있음).

### 4.3 OpenAI
- Responses API: `POST https://api.openai.com/v1/responses`, `Authorization: Bearer`, `"stream": true`.
- 화면에 쓰는 이벤트는 `response.output_text.delta`(필드 `delta`), 종료는 `response.completed`, 오류는 `error`.
- **모델 ID는 코드에 박지 않고** 사용자가 입력한다 (최신 모델명을 여기서 단정하지 않는다).
- 재시도·오류 분류는 Claude와 같은 규칙.

## 5. 노치 UX

### 5.1 진입
- 홈에 새 페이지 `chat` 추가 (`HomeOption`에 추가, 설정 → 기본에서 켜기·순서 변경, **기본 꺼짐**).
- 입력 칸은 메모의 방식을 재사용한다: 평소에는 가벼운 SwiftUI 글자, 누를 때만 실제 입력 칸(AppKit)을 띄워 메모리를 아낀다. 노치 창의 키 포커스 처리(`makeKey`, `releaseKeyFocus`)도 메모와 같다.

### 5.2 입력
- `Enter` 전송, `⇧Enter` 줄바꿈, `Esc` 답변 중이면 중지·아니면 닫기.
- **한글 조합 중(`hasMarkedText`)에는 `Enter`를 전송으로 보지 않는다** (한글 입력에서 마지막 글자가 중복 전송되는 문제 방지). 시험 항목.
- ⌘C/⌘V/⌘A는 기존 `handleEditingShortcut`이 처리한다.

### 5.3 답변 표시
- 크기는 AI 사용량(`usageSize`)보다 세로를 더 키운 `chatSize` 상수를 따로 둔다. 길면 스크롤.
- 스트리밍 중에는 맨 아래로 자동 스크롤하되, 사용자가 위로 올리면 자동 스크롤을 멈춘다.
- **토큰마다 화면을 갱신하지 않는다.** 60~100ms 단위로 모아 한 번에 갱신한다 (노치 전체 재계산이 CPU를 쓰는 것이 이 앱의 가장 큰 위험이다).
- 스트리밍 중에는 일반 `Text`, **완료된 뒤 한 번만** 마크다운(`AttributedString`)으로 변환한다. 코드 블록은 고정폭 글꼴 정도로 단순하게.
- 아이콘: 복사, 새 대화(메모와 같은 ✎ 스타일), 모델 이름 표시.

### 5.4 접힌 상태에서의 알림
- 노치가 접힌 채 답변이 끝나면 상세 알림 한 장: "답변 도착" + 첫 줄 요약. 누르면 채팅 페이지로 열린다.
- 새 `ActivityKind`(예: `.chat`)와 우선순위는 `info` 수준으로 둔다. 통화·잠금·HUD보다 낮다.
- 오류도 같은 카드로 짧게 표시한다 (키 없음, 한도 초과, 네트워크 끊김 등).

## 6. 자원 예산 (이 프로젝트의 기준)

| 상황 | 기준 |
|---|---|
| 채팅을 끈 상태 | **기존 수치 그대로**: 대기 CPU 0.15–0.25%, 메모리 17MB, 깨어남 0, 새 타이머·폴링 없음 |
| 대화 데이터 | 채팅 페이지가 보일 때만 메모리에 두고, 닫은 뒤 5초 후 폐기 (메모의 `unloadDelay` 방식) |
| 문맥 길이 | 최근 N턴(예: 12턴)과 글자 수 상한으로 잘라 보낸다 (비용·메모리 동시 보호) |
| 스트리밍 중 | CPU 상한을 측정해 릴리스 노트에 적는다. 화면 갱신 묶음 간격은 이 측정으로 조정 |
| 반복 | 질문 20회 반복 후 `leaks` 0건, 메모리가 질문 수에 비례해 늘지 않을 것 |
| 상한 | 기존 메모리 지킴이 한도(70MB) 안에서 동작 |

| M4 | 자원 시험, README·설정 안내문·릴리스 노트, 1.3.0 | §6 기준 충족, 평소 릴리스 시험 통과 |

**M1 구현 현황 (2026-11-05, 로컬 커밋):** 설정 → AI 채팅(서비스·서비스별 모델·키·연결 테스트), 키체인 저장, `ChatClient`(스트림·재시도·오류 분류). 문서보다 넓어진 점: **Gemini도 API 키로 포함**. 정한 값: Claude 기본 모델 `claude-opus-5-5`(메뉴에서 변경), 5.5 모델은 effort `low`, 출력 상한 4096, Claude는 `fallbacks: "default"`(Haiku 제외), OpenAI는 `store: false`. 연결 테스트는 모델 조회라 토큰을 쓰지 않는다. **실제 키로 답변을 받는 시험은 아직 안 했다.**

**M2·흐름 변경 (2026-11-05, 사용자 요청, 로컬 커밋):** 아래 §3·§5·§6의 해당 내용보다 이 항목이 우선한다.
- 기본 모델은 `claude-haiku-5-5`.
- 실시간 표시 없음: 답변을 다 받은 뒤 한 번에 보여 준다. 화면 갱신이 답변 끝에 한 번뿐이라 §5.3의 묶음 갱신은 필요 없어졌다.
- 작은 노치(제목 + 입력 칸) → 보내면 입력 칸 대신 "생각 중…"과 중지 버튼 → 완료되면 큰 노치(대화 + 입력 칸) → 재질문하면 다시 작은 노치. 입력 칸 안내 글자는 "무엇이든 물어보세요".
- 페이지가 안 보일 때 끝나면 상세 알림("답변 완료"/"답변 실패"), 누르면 그 채팅으로.
- **채팅은 메모처럼 저장한다** (`~/Library/Application Support/DynamicMacNotch/Chats/<id>.json`, 폴더 권한 700). 이름은 첫 질문으로 자동으로 붙고 제목을 눌러 바꾼다. 목록(오른쪽 1/3)에서 불러오고 우클릭으로 삭제한다. 페이지가 닫히면 5초 뒤 메모리에서 내리고 답변을 기다리는 동안은 유지한다. §3의 "메모리에만" 항목은 폐기.

**공통 프롬프트·출력 (2026-11-05):** 모든 서비스에 같은 지시(오늘 날짜, 모르거나 최근 내용은 웹 검색, Markdown·링크·LaTeX 형식)를 넣는다. Claude는 비스트리밍으로 받고 `pause_turn`을 이어 보낸다. 검색을 지원하지 않는 모델이 400을 주면 검색 없이 다시 묻는다. 수식은 외부 라이브러리 없이 `MathTypesetter`(STIX Two Math + CoreText)로 그리고, 못 그리는 수식은 원문을 보여 준다. SwiftMath 도입은 권한 정책에 막혀 쓰지 않았다. 링크는 http(s)만 기본 브라우저로 열고, 마우스를 올리면 실제 주소를 보여 준다. §3의 "모델 출력 링크" 항목의 누를 수 없음 결정은 이것으로 바뀌었다.

**키체인 한계:** ad-hoc 서명이라 지정 요구사항이 번들 ID뿐이다. 재빌드해도 암호 창 없이 읽히는 대신(확인함), **같은 번들 ID로 서명한 다른 앱도 키를 읽을 수 있다.** Developer ID로 서명하면 해결된다.

개발 빌드 전용으로 `chatsim:` 같은 명령을 두어 **키 없이** 가짜 스트림을 흘려 UI를 시험한다 (배포 빌드에는 포함하지 않는다).
