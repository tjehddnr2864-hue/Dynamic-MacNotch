# 실시간 모니터링 (AI 사용량 + 자원 사용량) 구현 가이드라인

작성: 2026-11-09 · 결정 반영: 2026-11-09 (§9) · R2·R1·R3·R4·R5 구현됨 · 버전은 배포할 때 정한다 (번호를 말하지 않으면 1.4.2)

AI 사용량 상시 표시에 CPU·GPU·메모리·네트워크 사용량을 더하는 기능의 구현 방향, 일어날 수 있는 충돌·오류와 해결, 작동 방식, 구현 순서를 정리한다.
수치는 이 Mac(MacBook, Apple Silicon 14코어, 메모리 26GB, macOS 27.3)에서 직접 잰 값이다. 코드 위치는 작성 시점(1.4.1)의 파일과 줄이다.

---

## 0. 결론

1. **AI 사용량과 자원 사용량은 서로 다른 홈 기능이다.** 홈 기능에서 따로 켜고 끄고, 디스플레이마다 따로 고를 수 있다. 실시간 모니터링의 "둘 다"를 고르면 두 기능을 고른 디스플레이가 하나로 합쳐 보이고, 해제하면 원래대로 돌아간다 (§3.3).
2. **종류를 늘리되 기존 `.aiUsage`는 건드리지 않는다.** 자원은 새 종류 `.resource`, 합친 것은 `.monitor`. 노치 양옆의 칸 두 개가 무엇을 보일지만 정하면 세 경우가 모두 같은 구조다 (§3.2).
3. **자원은 "필요한 것만, 보이는 동안만" 읽는다.** 노치에 보이는 칸(0~2개)과 확장 화면(4개)을 합친 *수요*가 있는 동안만 타이머 하나가 돈다 (§4.2).
4. **읽는 비용은 작다.** CPU 34µs, 메모리 5µs, 스왑 1.5µs, 네트워크 48µs, GPU 920µs (§2). 네트워크 카운터는 32비트라 4GB마다 돌아서 인터페이스별 차이로 계산한다.
5. **진짜 비용은 화면 다시 그리기다.** 값을 활동(`NotchActivity`) 안에 넣으면 매초 노치 전체가 다시 그려진다. 값은 별도 저장소에 두고 작은 뷰만 갱신한다 (§4.3).
6. **메모리 누적은 구조로 막는다.** 그래프 기록은 길이가 정해진 버퍼에만, 측정이 멈추면 비운다. 장시간 시험이 합격 조건이다 (§4.6, §7).

## 2. 측정한 사실

`scripts/resource-bench.swift`로 잰 값이다 (평균, 200~2000회).

### 2.1 읽는 비용

| 지표 | 방법 | 1회 비용 | 비고 |
|---|---|---|---|
| CPU | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` 두 번의 차이 | **34µs** | 14코어. 호출마다 mach 메모리가 할당되어 **`vm_deallocate`를 꼭 해야 한다** |
| 메모리 | `host_statistics64(HOST_VM_INFO64)` | **5.4µs** | 앱·압축·와이어드를 한 번에 |
| 스왑 | `sysctlbyname("vm.swapusage")` | **1.5µs** | 이 Mac: 0.21GB / 1.07GB |
| 네트워크 | `getifaddrs`의 링크 계층 `if_data` | **48µs** | **32비트 카운터**(4GB마다 한 바퀴). 이 Mac의 수신 누계는 이미 3.8GB |
| 네트워크 (비교) | `sysctl(NET_RT_IFLIST2)`의 64비트 카운터 | 572µs | 12배 비싸다. 쓰지 않는다 |
| GPU | `IOAccelerator`의 `PerformanceStatistics` | **920µs** | 가장 비싸다. 레지스트리 속성 사전을 통째로 만든다 |

- 네 지표를 모두 매초 읽어도 약 1ms/초(CPU 0.1%). 칸에 보이는 1~2개(예: CPU+메모리)는 40µs/초로 무시할 수 있다. **GPU를 고른 때만 비용이 눈에 띈다.**
- GPU 키 `Device Utilization %`(그 밖에 `Renderer Utilization %`, `Tiler Utilization %`)가 이 Mac에 있다. 비공개 레지스트리 키라 macOS 업데이트로 바뀔 수 있다 → §6.

### 2.2 지표 정의

| 지표 | 노치 칸 | 확장 화면 | 정의 |
|---|---|---|---|
| CPU | 사용률 % | 사용률 + 최근 60회 그래프 | 전체 코어의 (user+system+nice) 틱 ÷ 전체 틱, 두 샘플의 차이 |
| GPU | 사용률 % | 사용률 + 그래프 | `Device Utilization %` |
| 메모리 | 사용률 % | **가로 막대 하나**: 앱 · 압축 · 와이어드를 색으로 나누고 사용률 %, 아래에 네 값(앱·압축·와이어드·스왑, GB) | 앱 = internal − purgeable, 사용 = 앱 + 와이어드 + 압축 (활동 상태 보기의 '사용한 메모리'). 스왑은 디스크에 있어 %에는 넣지 않고 양만 보인다 |
| 네트워크 | 받기·보내기 속도 (위 ↑, 아래 ↓ 두 줄) | 두 속도 + 그래프(받기·보내기 두 선) | 물리 인터페이스(`en*` 등)의 바이트 차이 ÷ 경과 시간. `lo`·`utun`·`awdl`·`llw`·`bridge`·`anpi`·`gif`·`stf`·`ipsec`는 뺀다 |

- 이 Mac의 메모리: 앱+와이어드+압축 = 15.0GB / 25.8GB = 58%. `top`의 `PhysMem 23G used`와 다르다. `top`은 파일 캐시까지 센다. **구현 때 활동 상태 보기와 직접 대조한다 (R1).**
- 네트워크에서 `utun`을 빼는 이유: VPN을 쓰면 같은 데이터가 `utun`(암호화 전)과 `en0`(암호화 후)에 두 번 잡힌다. 물리 인터페이스만 세면 실제로 오간 양과 맞다.
- 네트워크 32비트 카운터: **인터페이스마다 `UInt32` 감소 연산(`&-`)으로 차이를 구한 뒤 더한다.** 한 간격 안에 4GB를 넘게 주고받지 않는 한 맞다 (10초 간격이면 초당 430MB, 1초면 4.3GB). 넘을 수 있는 환경(10GbE)은 §6.
- 네트워크 단위: 노치 칸은 폭이 좁아 `999K`·`12.3M`·`1.2G`처럼 B/s를 뺀 짧은 글자, 확장 화면은 `12.3 MB/s`.

### 2.3 R1에서 잰 것 (개발 빌드, 1초 간격)

| 상황 | CPU | 깨어남 | 메모리 |
|---|---|---|---|
| 기능 꺼짐 (측정 객체 없음, 타이머 0개) | 0.12% | 2.1회/초 | 16.8MB |
| CPU·메모리 칸, **매 틱 활동을 다시 게시** (지금 구조) | **3.08% / 3.37%** (두 번) | **31~34회/초** | 17.4MB |
| CPU·메모리 칸, **활동 한 번 + 작은 뷰만 갱신** (§4.3) | **0.32% / 0.30%** | **2.0회/초** | 17.4MB |
| 네 지표 + 칸 그리기, 10분 연속 | 평균 0.56% | | 17.5 → 18.5MB (4분 뒤부터 평탄), `leaks` 0건 |

- **§4.3의 설계가 맞다.** 활동을 매 틱 바꾸면 노치 전체가 다시 그려져 CPU가 약 10배, 깨어남이 15배다.
- 간격 1·2·5·10초에서 20초 동안의 측정 횟수 21·10·4·2회. 수요를 거두면 즉시 타이머가 멈추고 값·기록이 비워진다. 그래프 기록은 지표마다 60개에서 더 늘지 않는다.
- 정확도: 평소 CPU 12% (`top` 11%), 부하 4개 35% (`top` 35.9%). 내려받기 중 받기 7.8MB/s. GPU는 `IORegistryEntryCreateCFProperty`로 한 키만 읽는다.
- 처음 10분 측정에서 4분쯤 시험 앱이 사라졌다 (충돌 보고서·시스템 기록 없음). 같은 조건의 재측정은 10분을 끝까지 마쳤다. 원인을 찾지 못했으므로 R6의 1시간 측정에서 다시 본다.

### 2.4 아직 재지 못한 것

- 1시간 연속 측정 때의 메모리 증가 (R6)
- GPU를 한 키만 읽을 때의 1회 비용 (전체 사전 920µs와 비교)
- 확장 화면의 그래프 세 개를 매초 그리는 비용

## 3. 요구 정리

### 3.1 용어

| 한국어 | English | 비고 |
|---|---|---|
| 실시간 모니터링 | Live Monitoring | 설정 페이지 이름. 지금의 "AI 사용량" 페이지를 바꾼다 |
| AI 사용량 | AI Usage | 홈 기능·상시 항목 이름은 그대로 |
| 자원 사용량 | Resource Usage | 새 홈 기능·상시 항목 |
| AI 및 자원 사용량 | AI & Resource Usage | 통합해 보일 때의 이름 |
| 표시할 항목 | Show | AI 사용량 / 자원 사용량 / 둘 다 |
| 칸 (왼쪽·오른쪽) | Left, Right | 노치 양옆의 값 하나 |
| 메모리 / 네트워크 | Memory / Network | 칸의 작은 이름은 `CPU`·`GPU`·`MEM`·`NET` |

저장 키와 `SettingsPage.aiUsage`의 rawValue, `ActivityKind.aiUsage`, 홈 기능 키 `usage`는 **바꾸지 않는다** (저장된 설정·순위·디스플레이 선택이 이 이름으로 저장되어 있다). 화면에 보이는 이름만 바꾼다.

### 3.2 칸 규칙

노치 양옆의 칸 두 개를 `(왼쪽, 오른쪽)`으로 본다. 고를 수 있는 항목은 `aiPrimary`(AI 첫째 한도), `aiSecondary`(AI 둘째 한도), `cpu`, `gpu`, `mem`, `net` 여섯 가지다.

| 표시할 항목 | 왼쪽 | 오른쪽 | 고르는 방법 |
|---|---|---|---|
| AI 사용량 | 첫째 한도 | 둘째 한도 | 고정. 서비스만 고른다 (지금과 같음) |
| 자원 사용량 | CPU·GPU·메모리·네트워크 중 하나 | 나머지 중 하나 | 한쪽을 고르면 반대쪽 목록에서 그 항목이 비활성 |
| 둘 다 | 여섯 항목 중 하나 | 여섯 항목 중 하나 | 같은 항목을 양쪽에 둘 수 없다 (같은 방식으로 비활성) |

- 자원 전용과 둘 다의 선택은 **모드마다 따로 기억한다** (`resourceLeft/Right`, `bothLeft/Right`). 기본값은 자원 전용 CPU·메모리, 둘 다 AI 첫째 한도·CPU.
- 저장값이 그 모드에서 불가능하거나 양쪽이 같으면 순수 함수 `MonitorLayout.slots`가 기본값으로 푼다. 저장값은 바꾸지 않는다.
- AI 항목을 골랐는데 로그인한 서비스가 없으면 칸은 `–`, 설정에 "로그인 필요".

### 3.3 디스플레이별 표시와 통합 (결정 1)

- **AI 사용량과 자원 사용량은 서로 다른 콘텐츠다.** 홈 기능에서 각각 켜고 끈다. 둘 다 켜져 있으면 다른 상시 표시 항목처럼 디스플레이마다 따로 고를 수 있다 (메인 = AI 사용량, 보조 = 자원 사용량).
- **"둘 다"를 고르면** 두 기능 중 하나라도 고른 디스플레이는 합친 "AI 및 자원 사용량"(`.monitor`)을 보인다. **"둘 다"를 해제하면 원래대로 돌아간다.** 저장값은 건드리지 않고 읽을 때만 바꿔 해석하기 때문이다.
- 표시할 항목이 AI 사용량 또는 자원 사용량일 때: "모든 상시 표시"·"주 디스플레이와 같게"로 둔 디스플레이에 무엇이 뜨는지를 정한다. 디스플레이에서 직접 고른 항목은 그대로 보인다.

| 단계 | 표시할 항목 | 메인(저장값) | 보조(저장값) | 화면 | 도는 것 |
|---|---|---|---|---|---|
| ① | AI 사용량 | AI 사용량 | 자원 사용량 | 메인 AI, 보조 자원 | AI 새로고침 + 자원 측정(보조가 보이는 동안) |
| ② | **둘 다** | (그대로) | (그대로) | 두 디스플레이 모두 AI 및 자원 사용량 | 통합 활동 하나 |
| ③ | AI 사용량으로 복귀 | AI 사용량 | 자원 사용량 | ①과 같음 | ①과 같음 |

- 설정 → 디스플레이의 목록은 둘 다일 때 두 줄 대신 **"AI 및 자원 사용량"** 한 줄을 보인다(`kind:monitor`). 이때 직접 고르면 `kind:monitor`가 저장되고, 둘 다를 해제하면 표시할 항목의 종류로 푼다.
- "모든 상시 표시"(`all`)는 **표시할 항목에 포함된 종류만** 포함한다. 보조가 자원을 직접 골라 자원 활동이 돌고 있어도 메인의 "모든 상시 표시"에 자원이 끼어들지 않는다.
- **활동이 존재하는 조건**: 어떤 종류는 *켜진 디스플레이 중 하나라도 실제로 그 종류를 보일 때만* 게시한다 (`neededMonitorKinds`, 순수 함수, `--display-probe`로 조합 시험).

### 3.4 길게 눌렀을 때 확장 컨텐츠 (결정 5)

설정 `monitorExpand`(꾹 눌렀을 때 보일 내용): **표시할 항목을 따름**(기본) / AI 사용량 / 자원 사용량 / 둘 다. 켜진 기능만 고를 수 있다.

- AI 사용량: 지금과 같다 (AI만 상시일 때 홈의 AI 사용량 페이지, 그 밖에는 팝업).
- 자원 사용량: 홈의 자원 사용량 페이지 또는 팝업 (AI와 같은 규칙).
- 둘 다: 팝업 안에 페이지 두 개를 점으로 넘긴다. `persistentPages`가 `.monitor`를 두 페이지로 펼쳐 기존의 점·두 손가락 넘기기를 그대로 쓴다.

### 3.5 AI 한도가 하나뿐인 경우 (결정 2)

지금은 왼쪽에 사용률, 오른쪽에 초기화까지 남은 시간이다. 바꾼 뒤:

- **왼쪽 = 서비스 기호, 오른쪽 = 그 한도의 사용률.** 초기화 시간은 확장 화면에 남는다.
- 한도가 하나인 경우는 ChatGPT 무료(30일)뿐 아니라 **Claude Ultra처럼 5시간 한도 없이 주간 한도만 있는 요금제**도 포함한다. 그래서 "첫째 한도"는 *5시간 한도*가 아니라 *기간이 가장 짧은 한도*, "둘째 한도"는 *그다음 한도*로 정의한다. 한도가 하나면 첫째 = 그 한도, 둘째 = 없음.
- 둘 다 모드에서 `aiSecondary`가 없는 서비스: 오른쪽 칸에 서비스 기호 대신 초기화까지 남은 시간(지금 방식)을 보인다.
- **R3에서 확인할 것**: Claude 사용량 페이지 읽기(`UsageWeb`)가 5시간 한도가 없을 때 주간 한도를 놓치지 않는지. 지금 파서가 5시간을 전제하는 곳이 있으면 고친다. 계정이 없어 실제 화면으로 시험할 수 없으므로 저장된 응답 견본으로 시험한다.
- 설정 메뉴의 이름은 "AI 5시간 (없으면 주간)"과 "AI 주간"으로, 한도가 하나뿐인 요금제는 그 한도를 보인다고 안내한다.

### 3.6 홈 기능과 실시간 모니터링의 연동 (결정 1-1)

두 화면 모두 `AppSettings.setHomeFeature`를 부르므로 규칙을 한 곳에 둔다.

| 상황 | 결과 |
|---|---|
| 둘 다인데 홈에서 AI 사용량을 끔 | 표시할 항목이 **자원 사용량**으로 바뀐다 |
| 둘 다인데 홈에서 자원 사용량을 끔 | **AI 사용량**으로 바뀐다 |
| AI 사용량인데 AI를 끔 (자원은 켜짐) | 자원 사용량으로 바뀐다 |
| 둘 다 끔 | 표시할 항목은 그대로 두고 상시 표시가 사라진다 (보일 것이 없음) |
| 다시 켬 | 표시할 항목을 되돌리지 않는다. 사용자가 다시 고른다 |

- 저장값을 실제로 바꾸는 이유: "둘 다"가 해제된 것이 설정 화면에 그대로 보여야 꼬였다고 느끼지 않는다.
- 안전장치: 다른 경로(설정 파일 직접 수정 등)로 맞지 않는 값이 생겨도 읽을 때 `MonitorLayout.effectiveContent`가 켜진 기능으로 제한한다.
- 설정 화면은 꺼진 기능을 선택지에서 뺀다. 하나만 켜져 있으면 그 하나만 보이고, 다른 하나는 홈 기능에서 꺼져 있다고 안내한다.
- 꾹 눌렀을 때 보일 내용(`monitorExpand`)도 같은 방식으로 꺼진 기능을 빼고, 맞지 않으면 "표시할 항목을 따름"으로 해석한다.

### 3.7 서비스 기호 (결정 3)

서비스를 구분할 수 있으면 충분하다. 코드로 그린 도형을 서비스 색으로 칠한다 (Claude: 방사형 별, Gemini: 네 꼭지 별, ChatGPT: 꽃잎 고리). 원본 로고 이미지는 쓰지 않는다. 비슷한 모양과 지금 쓰는 서비스 색(`AIService.tint`)으로 구분한다.

## 4. 구조

### 4.1 종류와 활동

```
UsageStore ──(AI 값, 분 단위)──┐
                                ├─ 활동 게시: .aiUsage / .resource / .monitor
ResourceSampler ──(자원 값)────┘
                    ▲ 수요(어떤 지표가 보이는가)
                    └─ NotchHub (디스플레이별 표시 상태에서 집계)
```

| 종류 | 언제 게시 | 칸 내용 |
|---|---|---|
| `.aiUsage` (기존) | AI가 필요할 때 | 첫째·둘째 한도 (§3.5) |
| `.resource` (새) | 자원이 필요하고 통합이 아닐 때 | 자원 전용 칸 두 개 |
| `.monitor` (새) | 둘 다 | 둘 다 칸 두 개 |

- 우선순위 목록에는 `자원 사용량` 한 줄을 `AI 사용량` 바로 아래에 넣는다(`defaultPersistentOrder`에 `resource`, 기존 사용자는 자동으로 뒤에 붙는 규칙이 있다). `.monitor`는 자기 줄이 없고 **두 순위 중 높은 쪽**을 쓴다.
- `.resource`·`.monitor`도 `pagedKinds`에 넣는다.

### 4.2 ResourceSampler

새 파일 `Monitors/ResourceSampler.swift`.

- **수요는 소유자별로 등록한다**: `compact(디스플레이)`, `expanded(디스플레이)`, `homePage(디스플레이)`. 합집합이 읽을 지표다. 디스플레이 A가 CPU·GPU, B가 메모리를 보이면 세 지표를 한 번씩만 읽는다.
- **타이머는 하나**: `DispatchSourceTimer`, 간격은 설정(1·2·5·10초), 허용 오차는 간격의 10~20%. 수요가 비면 `cancel()`하고 참조를 버린다. 처음 수요가 생길 때 만든다(lazy). 기능을 쓰지 않으면 객체도 없다.
- **지표별 읽기**: 수요에 없는 지표는 호출하지 않는다 (GPU를 고르지 않으면 920µs를 아예 쓰지 않는다).
- **첫 값**: CPU·네트워크는 두 샘플의 차이라 켜진 직후 값이 없다. 수요가 생기면 즉시 한 번 읽고 **0.25초 뒤에 한 번 더** 읽어 첫 값을 만든다 (그 전에는 `–`).
- **재개**: 직전 틱과 시간 차가 간격의 3배를 넘으면(잠자기 등) 그 차이는 버리고 첫 값 과정을 다시 한다.
- **한 틱은 `autoreleasepool`로 감싼다.** `host_processor_info`의 버퍼는 `vm_deallocate`, `getifaddrs`는 `freeifaddrs`, IORegistry 사전은 풀 안에서 해제한다. `leaks`는 mach 가상 메모리를 보지 않으므로 **코드로 보장하고 soak 시험으로 확인한다.**

### 4.3 값 저장소와 라이브 뷰

지금은 `center.setPersistent(activity)`가 바뀔 때마다 `ActivityCenter`가 알리고 `DisplayNotchState`가 전달해 노치 전체가 다시 그려진다.

- 새 `ActivityValue.metric(MonitorMetric, ring: Bool)`. **활동은 "이 칸에 CPU를 그려라"라는 내용만 갖고 값은 갖지 않는다.** 틱마다 활동이 바뀌지 않는다.
- 칸을 그리는 작은 뷰 `LiveMetricView`가 `ResourceReadings`(별도 `ObservableObject`)를 관찰한다. 값이 바뀌면 그 뷰만 다시 그려진다.
- 같은 값이면 알리지 않는다: 퍼센트는 정수, 네트워크는 표시 글자가 같으면 건너뛴다.
- 숫자는 `monospacedDigit`, 폭은 지금과 같은 `compactWing`.
- 색은 `UsageGlyph.color`(70%↑ 주황, 90%↑ 빨강). 네트워크는 색을 바꾸지 않는다. 표시 형태(텍스트/원형)는 `aiUsageStyle`을 함께 쓰되, 네트워크는 원형이 의미 없으므로 늘 글자다.
- 접근성: `accessibilityAddTraits(.updatesFrequently)`.
- **효과는 R1의 프로토타입 측정으로 확인한다.** 효과가 없으면 이 절을 고친다.

### 4.4 DisplayRules 변경

| 함수 | 하는 일 |
|---|---|
| `effectiveChoice(_:content:)` | 둘 다일 때 `kind:aiUsage`·`kind:resource`·`kind:monitor` → `kind:monitor`. 단일일 때 `kind:monitor` → 그 종류 |
| `persistentKinds(...)` 수정 | `all`은 표시할 항목에 포함된 모니터 종류만 |
| `neededMonitorKinds(contexts:content:)` | 실제로 게시해야 할 모니터 종류 집합 |

`DisplayProbe`에 표시할 항목 3종 × 디스플레이 선택 × 대체 켬/끔 × 홈 기능 켬/끔 조합을 더한다.

### 4.5 확장 화면

- `ResourcePage`(새, 홈 페이지와 팝업이 함께 쓴다): CPU·GPU·네트워크는 값과 **최근 60회 그래프**, 메모리는 **가로 막대 하나**(앱·압축·와이어드 색 구분, 오른쪽에 사용률 %)와 네 값(앱·압축·와이어드·스왑 GB). 크기는 `usageSize`에 맞추고 안 맞으면 자원 전용 크기를 `popupSize`에 더한다.
- 확장 중(그리고 홈의 자원 페이지가 보이는 동안)만 네 지표를 읽는다. 닫으면 **0.5초 뒤** 수요를 거둔다.
- 둘 다 확장: `persistentPages`가 `.monitor`를 `[.aiUsage, .resource]`로 펼친다.
- `pagedKinds`·`collapseIfActivityGone` 목록에 새 종류를 더한다.

### 4.6 누적을 막는 장치

1. **기록은 그래프용 고정 버퍼에만**: CPU·GPU·네트워크(받기·보내기) 각각 길이 60의 링 버퍼. 다 차면 가장 오래된 값을 덮어쓴다. 합쳐서 수 KB이고 늘지 않는다. 메모리는 그래프가 없으므로 최신 값만.
2. **그 지표의 측정이 멈추면 그 버퍼를 비운다.** 노치 칸에 CPU가 있으면 확장했을 때 CPU 그래프는 이미 채워져 있고, GPU는 연 순간부터 쌓인다.
3. **멈추면 전부 버린다**: 수요가 0이 되면 `reset()`으로 이전 틱·최신 값·버퍼를 지운다. `MemoryTrim.soon()`도 부르지만 **기대지 않는다** (xzone 할당기를 쓰는 최신 macOS에서는 돌려주는 양이 0이라는 주석이 있다).
4. **메모리 지킴이 연결**: `MemoryGuard.releaseCaches`에서 `ResourceSampler.compact()`(버퍼를 비우고 다시 쌓음).
5. **연속 측정 중 주기 정리**: 10분마다 `compact()`. soak 결과로 조정하고, 증가가 없으면 넣지 않는다.
6. **왜 이게 필요한가**: 이 앱은 할당기가 해제한 메모리를 운영체제에 잘 돌려주지 않아 "비우기"로 되돌릴 수 있는 양이 적다 (`MemoryGuard`·`MemoryTrim` 주석). 그래서 **애초에 쌓지 않는 구조가 본체이고**, 매초 그리기가 증가를 일으키는지는 장시간 시험이 판정한다. 마지막 안전망은 기존 `MemoryGuard`의 조용한 재시작이다.

### 4.7 측정을 멈추는 조건

| 조건 | 자원 측정 |
|---|---|
| 어느 디스플레이에도 자원 칸이 보이지 않음 (더 높은 상시 항목이 가림, 항목에서 제외, 노치 없음) | 정지 |
| 두 손가락으로 상시 표시를 숨김 | **정지** (AI 새로고침은 지금처럼 계속) |
| Mission Control로 숨김 / 화면 잠금 / 패널 숨김 | 정지 |
| 화면 꺼짐, 시스템 잠자기 | 정지 → 깨어나면 첫 값 과정 |
| 일회성 알림이 잠깐 가림 | 계속 |
| 홈 기능에서 자원 사용량을 끔 | 정지, 객체 해제 |
| 저전력 모드 | 간격을 2배로 (결정 5) |

수요 집계는 `NotchHub`가 맡고 300ms 모아서 넘긴다. 집계는 순수 함수 `ResourceDemand`로 분리해 `--monitor-probe`로 시험한다.

## 6. 일어날 수 있는 충돌·오류와 해결

| # | 상황 | 문제 | 해결 |
|---|---|---|---|
| 1 | 홈에서 AI 사용량을 끔 | AI 새로고침·상시 표시가 멈춘다 (지금 동작) | 자원은 영향을 받지 않는다. 표시할 항목은 §3.6 |
| 2 | 둘 다인데 한쪽 기능을 끔 | 둘 다가 남아 꼬임 | §3.6: 남은 쪽으로 바꾼다 |
| 3 | 설정 창과 노치 앱이 동시에 설정을 씀 | 값이 엇갈림 | 홈 기능·표시할 항목은 설정 창에서만 바뀐다. 같은 함수에서 함께 저장하고 본 앱은 다시 읽는다 |
| 4 | 매초 값이 바뀌어 `ActivityCenter`가 계속 갱신 | 노치 전체 다시 그리기 | §4.3 |
| 5 | `host_processor_info`·`getifaddrs` 해제 누락 | 도구에 안 잡히는 누수 | `vm_deallocate`·`freeifaddrs`, soak로 확인 |
| 6 | CPU·네트워크 첫 값 | `0%`·`0K` 거짓 값 | 0.25초 첫 값 과정, 그 전에는 `–` |
| 7 | 잠자기 뒤 첫 값 | 긴 시간 평균으로 튐 | 간격의 3배를 넘으면 버림 |
| 8 | 네트워크 32비트 카운터가 한 바퀴 | 차이가 음수·거대한 값 | 인터페이스별 `UInt32` 감소 연산. 한 간격에 4GB를 넘으면 틀린다(10초 간격 + 10GbE). 이런 값(간격당 4GB 근처)은 버리고 직전 값을 유지 |

| 11 | GPU 키가 없음 | 값이 `–`로 굳거나 계속 시도 | 연속 3번 실패하면 읽기를 멈추고 설정에서 GPU를 비활성으로 표시 |
| 12 | GPU를 1초 간격으로 | 920µs/초 | 허용. R1에서 한 키만 읽는 방법이 더 싼지 측정 |
| 13 | 디스플레이 둘이 서로 다른 칸 | 같은 지표를 두 번 읽음 | 수요 합집합을 한 번에 읽고 공유 |
| 14 | 메인 AI, 보조 자원일 때 "모든 상시 표시" 디스플레이 | 자원이 끼어듦 | `all`은 표시할 항목에 포함된 종류만 |
| 15 | 둘 다로 바꿨다가 되돌림 | 직접 고른 값 소실 | 저장값은 그대로, 읽을 때만 해석 |
| 16 | 두 칸이 같은 항목 | 의미 없음 | 메뉴에서 비활성 + `MonitorLayout`이 풀어 줌 |
| 17 | AI 칸을 골랐는데 로그인 없음 | 빈 칸 | `–`, 설정에 "로그인 필요" |
| 18 | 5시간 한도가 없는 요금제 | 왼쪽이 늘 `–` | §3.5: 기간이 가장 짧은 한도가 첫째 |
| 19 | 우선순위에서 자원이 미디어 아래 | 음악이 나오면 자원이 가려짐(측정도 쉼) | 의도된 동작. 우선순위 안내에 한 줄 |
| 20 | 미리보기가 측정을 켬 | 끝난 뒤 타이머가 남음 | 자원 미리보기는 가짜 값만, 측정을 켜지 않는다 |
| 21 | 설정 창에서 값을 바꿈 | 반영 지연 | 기존 분산 알림 경로, 300ms 모아서 타이머 재생성 |
| 22 | `MemoryGuard` 재시작 | 상태 소실 | 그래프만 비워진다. 재시작 뒤 수요 집계가 다시 시작 |
| 23 | 노치 없음 디스플레이, 디스플레이 연결·해제 | 수요가 남음 | 켜진 디스플레이만 집계, `tearDown` 때 그 소유자 해제 |
| 24 | 색 임계값 | CPU 70%는 자주 넘음 | AI와 같게 시작, 거슬리면 CPU만 90%/98% (R3) |
| 25 | 홈에 새 페이지가 생김 | 기존 사용자 홈에 "자원 사용량"이 추가됨 | 기본 켜짐, 홈 마지막. 업데이트 노트에 안내 |

## 7. 자원 예산과 시험

### 7.1 합격 기준 (제안, R1 측정 뒤 확정)

| 항목 | 기준 |
|---|---|
| 자원 칸·자원 페이지가 보이지 않을 때 | **추가 비용 0**: 측정 객체 없음, 타이머 0개, 실행 직후 메모리·대기 CPU가 1.4.1과 같음 (17.2MB / 0.07~0.10%) |
| 칸 1~2개(CPU·메모리), 1초 | 대기 CPU ≤ 0.5%, 메모리 +1MB 이내, 대기 깨어남 +1/초 이내 |
| 확장 화면(4지표·그래프 3개) 열림, 1초 | CPU ≤ 1.5% (열려 있는 동안) |
| 확장을 닫은 뒤 | 1초 안에 쓰지 않는 지표 중단, 수요가 0이면 타이머 0개 |
| 연속 1시간 측정(1초, CPU+GPU+네트워크) | 시작 5분 이후 메모리 증가 ≤ 2MB, `leaks` 0건 |
| 확장·축소 50회 | 메모리 증가 없음 |
| 컴파일 경고 | 프로젝트 코드 0건 |

### 7.2 시험 항목

- `--monitor-probe`: 표시할 항목·칸 해석, 홈 기능 연동(§3.6), 수요 집계, 통합 해석의 가역성, `.monitor` 순위.
- `--display-probe`·`--settings-probe` 확장.
- `notchctl monitorstate`: 읽는 지표, 간격, 타이머 유무, 틱 수, 메모리.
- 실제 화면: CPU 부하(`yes > /dev/null`), 큰 파일 내려받기로 네트워크, 메모리를 활동 상태 보기와, GPU를 활동 상태 보기의 GPU 기록과 대조.
- 외부 디스플레이가 없으면 다중 디스플레이(§3.3)는 규칙 시험과 `devdisplay`로 확인하고 실제 연결 시험은 사용자에게 맡긴다고 릴리즈 노트에 적는다.
- 배포 전: 배포 빌드로 §7.1을 재고 결과를 릴리즈 노트(두 언어)에 넣는다.

## 8. 구현 단계

단계마다 로컬에 커밋하고 배포는 요청이 있을 때만 한다. **R1과 R2는 서로 의존하지 않아 사용자 요청대로 R2를 먼저 했다.**

| 단계 | 내용 | 시험 / 확인 |
|---|---|---|
| **R0** | 읽는 비용·가용성 측정 — **완료** | §2.1, §2.2 |
| **R2** | 설정 모델: 새 키, 순수 함수 `MonitorLayout`(표시할 항목·칸·연동), 홈 기능 `resource`(홈 페이지는 준비 중 표시), 실시간 모니터링 페이지 — **완료**. 노치 표시는 아직 바뀌지 않는다 (AI 상시 표시는 지금처럼 `aiUsagePinned`만 따른다) | `--monitor-probe` 371건, `--settings-probe` 17건(홈 기능 연동 포함), 설정 화면 5가지 상태 캡처 |
| **R1** | `ResourceSampler`(수요·타이머·첫 값·정지·버퍼·`compact`), `ResourceReadings`, `ActivityValue.metric`·`LiveMetricView`(측정용으로 먼저), 개발 명령 `monitordemand`·`monitortest`·`monitorstate` — **완료**. 수요 합집합은 샘플러 안의 사전 하나라 별도 순수 함수(`ResourceDemand`)는 두지 않았다. 디스플레이 상태에서 수요를 모으는 일은 R4 | probe, 활동 상태 보기와 대조, 1·2·5·10초 × 1·2·4지표의 CPU·깨어남·메모리, 10분 soak |
| **R3** | `ActivityValue.serviceMark`·서비스 기호(`ServiceMark`), 한도 하나면 왼쪽 기호·오른쪽 사용률(주간만 있는 요금제 포함), `.resource`·`.monitor` 종류와 활동 조립(`MonitorActivity`), 게시(`MonitorCoordinator`, 표시할 항목 전역 기준), AI 새로고침은 AI가 보일 때만, 우선순위에서 자원 사용량을 AI 사용량 바로 아래에 넣기(기존 사용자 포함), 미리보기 2종 — **완료**. 가려짐·숨김 때 측정 정지와 디스플레이별 규칙은 R4 | `--monitor-probe` 386건(조립·Claude 응답 견본 포함), 노치 캡처 8가지 |
| **R4** | `DisplayRules.monitorMapped`(둘 다면 통합, 해제하면 원래 선택, 저장값 그대로)·`all`에서 다른 모니터 종류 제외·`neededMonitorKinds`, 설정 → 디스플레이 목록(둘 다면 한 줄), `NotchHub`가 디스플레이마다 실제로 보이는 칸만 측정(두 손가락 숨김·잠금·Mission Control·화면 꺼짐·더 높은 항목이 가리면 정지), 칸 메뉴에서 반대쪽 항목 빼기 — **완료** | `--display-probe` 6,257건(새 12건), 이 Mac(디스플레이 1개)에서 숨김·잠금 흉내·가림·둘 다·AI 전환 때 측정 대상 확인, `leaks` 0건. 디스플레이 2개 실제 시험은 외부 모니터 연결 뒤 |
| **R5** | `ResourcePage`(CPU·GPU·네트워크 그래프, 메모리 앱·압축·와이어드 막대와 스왑), 홈 페이지 `resource`, 꾹 눌렀을 때 내용(`monitorExpand`, "노치에 보이는 항목을 따름"은 누른 항목 기준), 둘 다면 팝업 두 페이지를 점으로 넘김, 확장 화면이 보이는 동안만 네 지표(홈 기능이 꺼져 있으면 열려 있어도 읽지 않음) — **완료**. 닫을 때 지연은 0.5초가 아니라 기존 수요 계산의 0.3초 묶음을 그대로 쓴다 | 열기·닫기 25회 `leaks` 0건, 수요 변화(칸 지표 ↔ 네 지표), 화면 캡처 3가지 |
| **R6** | 마무리: README·`ARCHITECTURE.md`, 전체 회귀, **1시간 soak**, 배포용 빌드 측정, 릴리즈 노트 | §7.1 전부 |
